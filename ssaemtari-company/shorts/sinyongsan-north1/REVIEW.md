# REVIEW — 신용산역 북측1구역 근생 쇼츠

## 정한 것

- **세로 9:16** 을 골랐다. 쇼츠 요청이고, 화면 아래 1/3(1330 px 아래)은 플랫폼 UI 자리라 읽을 글자를 두지 않고 장면 번호만 크게 깔았다.
- **줄거리 하나로 바로 만들었다.** 요청이 "영상 생성 후 표시"라 HyperFrames 의 세 갈래 줄거리 제안 단계는 건너뛰었다.
  흐름은 블로그 순서를 따른다: 훅(19.5억 상가) → 질문 → 추산서 숫자 → 근생 아파트 조건 → 판정 → 115A 비용 → 신축 비교 → 입지 → 시점과 고지 → 상담.
- **하드컷 플래시**: 장면 사이 9번, 장면 안 샷 사이 7번. 흰색과 노란색을 번갈아 쓰고, 빨간 플래시는 쓰지 않았다(광과민).
- **숫자 카운트업은 오도미터**로 만들었다. 렌더러가 탐색할 때 콜백을 건너뛸 수 있어, 글자를 바꾸는 대신 0~9 띠를 굴린다.
- 블로그의 "용산에서 최고" 같은 단정 표현은 넣지 않았다.

## 2차 수정 — 본인 목소리, 60초에 맞춘 대본

- 의뢰인 요청: 첫 버전 목소리(Supertonic F4)가 기계 같다 → 본인 녹음을 참고한 목소리로, 전문가 톤, 60초.
- 녹음 5개는 다른 구역 설명이라 대본으로 쓰지 않고 10초만 참고 음성으로 썼다. 비교 샘플 12개 중 의뢰인이 11번(또렷한 아나운서)을 골랐다.
- 본인 말 속도로는 원래 대본이 약 94초라, 숫자 화면은 그대로 두고 말을 약 300음절로 줄였다.
- 첫 버전이 기계 같았던 원인 추정: 쉼표마다 끊어 합성 + 1.13배속. 이번엔 줄마다 통째로 합성한다.
- 시각을 손으로 넣지 않는다. 완성된 음성의 단어별 시각으로 장면·자막·효과음을 계산하도록 빌드를 바꿨다.

- 결과: 말소리 56.5초 + 끝 화면, 60.0초. 12줄 모두 Whisper 로 숫자 확인 통과. "평형"은 [평영](ㅎ 약화)으로 들려
  자연스러운 발음으로 보고 그대로 두었고, "지위"는 같은 소리 "지휘"로 인식돼 정확.
- 음량: 렌더 원본이 -12.4 LUFS 라 전체 믹스를 ×0.74(-2.6 dB) → -15.1 LUFS, 최대 -3.6 dBFS. build.py 의 MIX 에도 넣었다.

## 잰 것과 보기만 한 것

- `hyperframes check`: lint · runtime · layout · audio · contrast · motion 오류 0.
- 내레이션: 27개 절을 Whisper(medium)로 되읽어 숫자가 자막과 같은 TTS 시드를 골랐다. 전체 트랙도 줄마다 다시 확인했다.
  "업무"는 표준 발음 [엄무]라 인식기가 "연무"로 적지만 숫자는 모두 일치.
- 소리는 **측정만 했고 듣지 않았다**. 효과음은 파일마다 정점 시각을 재서 그림보다 한 프레임 뒤에 맞췄다.
- 장면별 스냅샷(시작·중간, 컷 전후)을 눈으로 확인했다.

## 일부러 남긴 경고

- `line_unread` — 끝 화면 고지문(31 단어, 약 2.7 s): 멈춰서 읽는 사람을 위한 작은 글씨. 같은 고지가 장면 5·9에도 짧게 나온다.

## 약한 곳과 다음에 할 것

- 진행자(아나운서)가 없다. 요청의 참고 사진이 첨부되지 않았다. 사진이 오면 장면 1·10에 넣거나, HeyGen 말하는 사진(로그인·크레딧 필요)으로 입 모양까지 맞출 수 있다.
- 배경음악이 없다(카탈로그는 HeyGen 로그인 필요). 내레이션과 효과음만 있다.
- 끝 화면에 중개사무소 소재지·연락처·등록번호·대표 성명이 없다. 광고로 올리려면 채워야 한다.
- 장면 7(비교, 10.7 s)이 가장 길고 정보가 많다. 줄이려면 0~45억 막대 비교를 빼고 한계선 비교만 남긴다.

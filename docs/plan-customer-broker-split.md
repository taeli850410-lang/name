# 랜드랭귀지(LAND LANGUAGE) 검토 및 고객용·중개사용 이원화 기획안

- 검토일: 2026-09-12
- 대상: https://kimyusoo.github.io/landlanguage-edm/ 의 데모 원본(EDM 미리보기.html, 1,900줄)과 화면 캡처 5장(DAILY 이메일 · WEEKLY · MONTHLY 인스타 주제 목록 · 인스타 카드 · 블로그 포스팅), 저장소의 안양 대시보드
- 한계: 라이브 사이트와 외부 사이트는 검토 세션의 네트워크 정책으로 직접 접속하지 못했다. 동일 코드의 데모 원본과 캡처로 검토했고, 링크는 검색 결과로 확인했다.
- 시각 자료가 포함된 판은 같은 폴더의 `plan-customer-broker-split.html` 참고.

## 0. 한눈에

- **검토 결론**: 디자인 시스템, 정책 단계 7분류, 보유형태별 영향도, 컴플라이언스 문구, 멀티채널 출력은 강점. 그러나 실시간 뉴스가 들어오는 순간 모든 카드의 해설이 같은 안내문 3줄로 덮여 "AI 브리핑"이 비고, 숫자는 데모값이라 헤드라인과 모순되며, 중개사에게 하는 말이 고객 발송물에 그대로 실린다.
- **분리 원칙**: "하나의 이슈 레코드, 두 개의 렌더링". 중개사용은 전체 이슈를 다루는 편집·실무 스튜디오, 고객용은 3~5개 이슈를 쉬운 말과 할 일, 공공데이터 바로가기로 담는 읽기 전용 레터.
- **보도자료 분류**: 발표 주체·정책 단계·주제·영향 대상·지역의 5축 태그 + 라우팅 규칙 8개(R1~R8).
- **공공데이터**: 수집 소스 12곳, 고객용 바로가기 22곳, 중개사용 바로가기 20곳, 주제별 자동 삽입 매핑, API 자동화 항목.
- **링크 표기**: ● 검색 결과로 URL 확인 / ○ 공식 도메인이나 접속 미검증.

## 1. 현재 사이트 검토

### 1.1 무엇으로 만들어져 있나

- 구성 축: 주기 3종(DAILY·WEEKLY·MONTHLY) × 출력 4종(이메일·모바일·인스타 카드·블로그) × 액션 5종(사무소·메일·PDF 인쇄·카카오톡·링크)
- 콘텐츠 단위: 이슈 12개 슬롯 = 정식 데모 이슈 5개(금리·공급·청약·세금·통계) + 범용 주제 7개(임대차·정비사업·대출·분양·GTX·전세가율·신도시). 각 이슈는 정책 단계, 기관, 한 줄 요약, 설명, 불릿 3개, 영향 요약, 대상 태그, 관련 기사, 보유형태 7종 영향도를 가진다.
- 실시간 데이터: GitHub Actions가 Google News RSS를 수집해 news.json을 커밋 → 페이지가 12개 슬롯의 제목·기사·링크를 교체
- 화면 순서(이메일): 마스트헤드 → 슬로건 → 헤드라인 → 정책 카드(4·6·8) → 뉴스 카드(8·12·12) → 오늘의 숫자(타일 6 + 막대) → 그래서 내 부동산에는?(7행) → 공인중개사의 한마디 → 상담 CTA → 푸터
- 저장: 모두 localStorage(서버·계정 없음, 기기 간 동기화 없음)
- 발송: mailto·Gmail 초안, 새 창 PDF 인쇄, 카카오 공유(SDK 키 미설정 → 클립보드 복사), 링크 복사(`?t=DAILY`만 포함)
- 저장소의 다른 자산: 안양(만안·동안) 실거래 대시보드(index.html)와 수집 스크립트(fetch.js·process.js·top10.js) → "우리 동네 숫자" 데이터 소스로 재사용 가능

### 1.2 잘 만든 것 (유지)

1. 정책 단계 7분류(확정·시행 예정·입법예고·국회 심의 중·정부 검토·언론 보도·전망/분석)
2. 보유형태 7종 영향도(무주택·1주택·다주택·매수 예정·매도 예정·임대인·임차인)
3. "출처와 기준일이 확인된 수치만 게시", 면책·광고성 정보 표시·수신거부 문구
4. 한 데이터로 네 채널 생성(이메일·모바일·1080×1350 인스타 카드·SEO 골격 블로그 초안)
5. 사무소 브랜딩 자동 반영, 섹션 인라인 수정·삭제·복원, 발행일 자동 계산
6. 에디토리얼 디자인 시스템(네이비·골드·오렌지)과 카드 가독성

### 1.3 문제점 (심각도순)

**P0 — 신뢰를 깨는 문제**

1. **실시간 모드에서 해설이 비어 있다.** news.json이 들어오면 `hydrateNews()`가 모든 이슈의 불릿·영향 요약·페르소나 영향도를 같은 문장으로 덮어쓴다. 캡처 기준 DAILY 12개, WEEKLY 18개 카드에 "헤드라인보다 적용 대상·시행 시점·구체 수치를 원문에서 먼저 확인하세요"가 반복되고 영향도는 전부 ●●●○○. → 수집 후 요약·태깅·영향도 생성 단계(LLM)와 검수 플래그를 파이프라인에 추가, 생성 실패 시 카드 숨김.
2. **숫자가 헤드라인과 모순된다.** '오늘의 숫자'는 코드에 고정된 데모 상수. 헤드라인은 "두 달 연속 기준금리 인상"인데 타일은 "기준금리 2.5% 보합(기준일 2026-09-02)". 한국은행 공시 기준 7.16 2.75%, 8.27 3.00%. '출처' 링크는 네이버 검색. → ECOS·R-ONE·실거래가 API로 채우고 출처는 실제 통계 페이지로.
3. **기관·단계 배지가 기사와 무관하다.** 배지는 주제 슬롯에 고정. "대전시의회, 둔산지구 재건축" 기사에 국토교통부, "특별공급 개편 이후 달라진 당첨 전략"에 입법예고, "종부세 개편"에 공식자료·언론 보도. → 배지는 레코드의 실제 메타에서만 렌더, 불확실하면 숨기고 '확인 필요'만.
4. **중개사에게 하는 말이 고객 발송물에 실린다.** "고객 상황에 따라 영향이 달라짐을 안내하세요", "구분해 설명하세요", 인스타 "공인중개사 POINT", 슬로건 "AI를 아는 중개사가 대체합니다". 푸터에는 "광고성 정보 수신에 동의한 고객에게 발송"이라고 적혀 있다. → audience 파라미터 분리 + 금지어 자동 차단(R7).
5. **공유 링크가 고객에게 '중개사 화면'을 보여준다.** 공유 URL은 같은 스튜디오 페이지이고 사무소 정보는 URL에 없다. 고객 브라우저에서는 "홍길동부동산", "연락처를 입력해 주세요", "카카오톡 채널 미설정"이 보이고, 첫 방문 모달 "중개사무소 정보 입력"이 뜨며(첫 방문에는 ESC·배경 클릭으로 닫히지 않음), 수정·삭제 버튼도 노출. → 사무소 정보를 포함한 읽기 전용 발행 스냅샷 URL.
6. **'확인 필요' 배지가 항상 켜져 있다.** 모든 카드에 무조건 표시되어 경고 의미 상실. → 원문 미확인·단계 불명·수치 미검증일 때만.

**P1 — 구조 문제**

7. 정책 섹션과 뉴스 섹션이 같은 배열(ISSUES)을 두 번 렌더 → 같은 카드·같은 관련기사 3건 반복. WEEKLY 캡처 세로 25,180px(2배율)로 DAILY의 1.7배. → 정책 = 기관 원문, 뉴스 = 언론 보도로 역할 분리, 같은 이슈는 한 번만.
8. DAILY인데 기사 날짜가 2~4주 전(08.27, 08.19, 08.01, 08.03). '발표일'은 첫 기사 날짜. → DAILY 48시간, WEEKLY 7일, MONTHLY 당월 컷.
9. "그래서 내 부동산에는?"이 첫 이슈에만 연결, 실시간 모드에서는 값이 전부 같아 정보량 0. → 이슈별 영향도, 고객용은 해당 세그먼트 행만.
10. 원문 링크 폴백이 네이버 검색("원문·관련보도 보기", "출처"). → 실제 URL 없으면 버튼 숨김, 보도자료는 공식 소스 URL로.
11. 발송 전 검증이 없다. 푸터는 "등록번호 브랜드설정에서 입력"이라 하지만 모달에 등록번호 칸이 없다. → 발행 전 체크(필수 사무소 정보·수신거부 링크·금지어·빈 카드).
12. 편집 모드와 읽기 모드가 나뉘어 있지 않다(미리보기 안에 수정·삭제 버튼). → 스튜디오와 레터를 화면·URL 수준에서 분리.

**P2 — 마감 문제**

13. 텍스트 겹침 3곳(정책 카드 불릿, 뉴스 카드 배지-제목, CTA 제목). 캡처 도구 문제일 수 있어 실기기 확인 필요.
14. 푸터·주석 글자 9.5~10.5px. 본문 최소 13px, 법적 고지 최소 12px 권장.
15. 인스타 카드 본문 슬라이드가 "원문에서 확인하세요" 안내문.
16. 블로그: 메타 설명이 본문에 렌더, 목차 앵커 없음, 실시간 모드에서 보유형태 표가 전부 3/5.
17. 접근성: 모달 포커스 트랩 없음, 선택 버튼에 aria-pressed 없음, 단계가 색으로만 구분되는 곳.
18. 수신거부·개인정보처리방침 링크가 `#`. 광고성 메일은 수신거부 수단이 실제로 동작해야 한다.
19. EDM인데 메일 발송 계층이 없다(메일 앱 초안·PDF 첨부 의존). 수신자 목록·발송 이력·반응 추적 없음.

### 1.4 개발자용 기술 메모

- Google News RSS는 제목·링크·짧은 요약만 주므로 해설 공백(1번)은 소스의 한계. 정부 보도자료 RSS를 1차 소스로, 언론 기사는 보강 자료로.
- 단일 파일을 `data`(이슈 레코드) / `render-letter`(고객용) / `render-studio`(중개사용)로 분리. 렌더 함수는 같은 레코드를 받아 audience에 따라 다른 필드를 쓴다.
- `agencyStyle`은 '기획재정부'만 인식. 최근 보도는 '재정경제부'. 기관 사전을 데이터로 분리.
- fetch.js에 공공데이터포털 서비스 키가 평문으로 커밋되어 있다. GitHub Actions Secrets로 옮기고 키 재발급 권장.
- 안양 대시보드의 주간·월간 중위가 지수와 TOP10 로직은 "우리 동네 숫자" API로 재사용. 실거래 신고 기한 30일 → 최근 두 달은 잠정치 주석을 고객용에도.

## 2. 고객용·중개사용 분리 설계

### 2.1 두 제품 정의

| 구분 | 중개사용 STUDIO | 고객용 LETTER |
|---|---|---|
| 사용자 | 개업·소속 공인중개사 | 중개사의 고객(매수·매도·임차·임대·청약 준비) |
| 읽는 이유 | 오늘 무엇을 알고, 누구에게 무엇을 보낼지 결정 | 내 상황에 무엇이 달라지는지 이해, 필요하면 상담 |
| 분량 | 수집된 전체(12~20개), 접기·필터 | DAILY 3 · WEEKLY 5 · MONTHLY 8 |
| 언어 | 실무 명령형, 법령·조문·수치 원문 그대로 | 2인칭 존댓말, 한 문장 30자 안팎, 용어 첫 등장 시 풀이 |
| 핵심 화면 | 인박스 · 이슈 상세 · 레터 빌더 · 마케팅 스튜디오 · 데이터 · 설정 | 헤드라인 · 이슈 카드 3~5 · 우리 동네 숫자 · 내 상황 체크 · 한마디 · 상담 CTA |
| 편집 | 가능 | 불가(발행 시점 읽기 전용 스냅샷) |
| 접근 | 로그인 또는 기기 인증 | 링크·메일·카카오, 로그인 없음 |
| 데이터 | 원자료 표, API, 잠정치 주의, 원문·법령 링크 | 안양 숫자 2~4개와 추세 한 줄, 실제 출처 링크 |
| 현재 사이트의 위치 | 도구막대·편집·인스타·블로그·사무소 설정 | 이메일·모바일 미리보기(편집 UI 제거 후) |

### 2.2 흐름

① 수집(정부 보도자료 RSS·API, 한은·금융위·부동산원, 경기도·안양시 고시공고, 언론 기사) → ② 자동 태깅·초안(5축 태그, 요약·영향도·할 일 초안, 중복 묶음, 검수 플래그, 규칙 R1~R8) → ③ 중개사 STUDIO(인박스에서 선택, 코멘트·순서·세그먼트, 발송 전 검증, 인스타·블로그 소재) → ④ 고객 LETTER(세그먼트별 3~5개 이슈, 우리 동네 숫자, 할 일·바로가기·CTA; 읽기 전용 URL) → 클릭·상담 요청·수신거부는 인박스로 회신. 지역 데이터 API(실거래·R-ONE·ECOS)는 ②·③에서 숫자 타일로 들어간다. 중개사 전용으로 분류된 이슈는 ③에서 멈춘다.

### 2.3 하나의 이슈 레코드, 두 개의 렌더링

| 필드 | 내용 | 중개사용 | 고객용 |
|---|---|---|---|
| agency · status · topic · region | 5축 태그 | 배지·필터 | 배지(기관·단계·날짜만) |
| published_at · effective_at | 발표일·시행일(D-day) | 표시 | 시행일 우선 |
| official_url · articles[] | 공식 원문, 관련 기사(≤4) | 전부 | 원문 1 + 기사 1~2 |
| fact_sheet | 대상·수치·일정·경과규정 | 표로 | 2문장 축약 |
| headline_plain | 고객용 20자 제목 | 참고 | 제목 |
| what_changes_for_me[segment] | 세그먼트별 한 문장 + 영향도 0~5 | 세 세그먼트 모두 | 해당 세그먼트만 |

### 3.2 라우팅 규칙 R1~R8

- **R1 단계로 1차 결정**: 확정·시행 예정·통계 발표·지자체 고시 → 고객용 본문 후보. 입법예고·국회 심의·정부 검토·언론 보도·전망 → 고객용은 주 1회 "지켜볼 이슈" 한 줄('확정 아님' 표시), 중개사용은 전 단계.
- **R2 중개업 제도는 중개사 전용**: 공인중개사법, 중개보수, 임장비, 확인·설명 의무, 전자계약, 협회, 행정처분·과태료. 시행 확정 시 고객 체감 변화만 한 줄(예: 공동관리비 설명 의무화 → "계약 전 관리비 내역을 요구할 수 있어요").
- **R3 지자체 고시는 동네 타깃**: 안양시 정비구역 지정·주민공람·특별정비구역·지구단위계획은 중개사 전용 전문 + 해당 동 거주·보유 수신자에게만 발송.
- **R4 세금·대출·청약은 양쪽, 깊이만 다르게**: 고객용은 "나에게 적용되나?" 체크 3개와 계산 바로가기(홈택스·기금e든든·청약홈). 중개사용은 요건표·경과규정·상담 스크립트·세무사 연계 기준.
- **R5 통계는 지역 숫자로 치환**: 고객용은 안양 숫자 2~4개와 추세 한 줄. 서울 통계는 안양 수치로 바꾸고 못 바꾸면 싣지 않음. 중개사용은 전체 표·원자료·잠정치 주석.
- **R6 언어 규칙**: 고객용은 2인칭 존댓말, 30자 안팎, 용어 풀이, 지시문은 고객 본인 행동에만. 중개사용은 체크리스트 명령형, 법령·수치 원문.
- **R7 고객용 금지 목록(자동 차단)**: "고객에게", "안내하세요", "설명하세요", "상담 시", "영업", "경쟁", "수주", "협회", "DEMO", 미입력 브랜드 필드. 걸리면 발행 차단.
- **R8 분량과 신선도**: 고객용 DAILY 3(48시간) · WEEKLY 5(7일) · MONTHLY 8(당월). 같은 이슈 중복 게재 금지. 중개사용은 제한 없이 접기.

### 4.5 API로 자동화할 수 있는 것

- 실거래가 API(공공데이터포털, fetch.js 사용 중): 안양 만안·동안 주간·월간 중위가 → "우리 동네 숫자" 타일 4개. 최근 두 달 잠정치 표기.
- 한국은행 ECOS API: 기준금리, 주택담보대출 금리(신규취급액). 데모 상수 두 개 대체.
- 한국부동산원 R-ONE API: 주간 매매·전세 가격지수(안양), 월간 거래량, 미분양.
- korea.kr·국토부 RSS: 보도자료 제목·본문 링크. 태깅 파이프라인 1차 입력.
- 경기도 보도자료 API(공공데이터포털 15034926).
- 건축물대장·토지 API: 중개사용 물건 조사 자동화.
- 안양시 고시공고: API 없음 → HTML 수집, 제목에서 동·구역명 추출.

## 5. 화면 구성과 UX 백로그

### 5.1 화면 구성안

**중개사용 STUDIO**
1. 인박스 — 수집 목록. 열: 시각, 주체, 단계 배지, 주제, 지역, 추천 등급(★ 발송 권장 · ◎ 참고 · ○ 보관), 중복 묶음. 필터: 오늘·이번 주, 안양만, 확정만, 미검수만.
2. 이슈 상세 — 팩트시트 → 원문·법령·기사 → 지역 영향 → 상담 스크립트 → 실무 체크리스트 → FAQ → 세그먼트 영향도 → [고객용 미리보기] 토글.
3. 레터 빌더 — 세그먼트 선택 → 자동 선정(R1~R8) → 순서·코멘트 편집 → 우리 동네 숫자 자동 → 발행 전 검증 → 미리보기 → 발행(읽기 전용 URL) → 발송.
4. 마케팅 스튜디오 — 인스타 카드·블로그 이관. 본문은 고객용 필드로, 금지어 동일 적용.
5. 데이터 — 안양 대시보드 통합 + 바로가기 패널.
6. 설정 — 사무소(등록번호 포함), 채널, 수신자 목록과 세그먼트·동 태그, 기본 문구.

**고객용 LETTER**
1. 마스트헤드 — 사무소명·대표·등록번호. 슬로건은 고객 문구("안양 부동산 소식, 3분 브리핑").
2. 오늘의 한 줄
3. 이슈 카드 3~5 — [주체·단계·날짜] 쉬운 제목 → 무슨 일(2문장) → 나에게는 → 지금 할 일(1~3) → 원문·바로가기
4. 우리 동네 숫자 — 안양 타일 4개와 6개월 추세, 출처·기준일, 잠정치
5. 지켜볼 이슈 — 주 1회, '확정 아님' 표시
6. 용어 하나
7. 중개사의 한마디 — 비어 있으면 섹션 제거
8. 상담 CTA — 미설정 채널 버튼 숨김
9. 푸터 — 사무소·등록번호·면책·광고 표시·실제 동작하는 수신거부. 글자 12px 이상

## 6. 로드맵

- **1~2주 신뢰 회복**: P0 5건, 고객용 렌더 분리와 금지어 필터, 실데이터 숫자 타일(안양 4개), 읽기 전용 발행 URL
- **3~6주 이원화 완성**: 5축 태깅과 R1~R8, 세그먼트 3종과 수신자 태그, 인박스·이슈 상세·레터 빌더, 바로가기 자동 삽입, 안양시 고시 수집과 동네 타깃
- **7주~ 서비스화**: 발송 계층과 수신거부, 클릭·상담 요청 회신, 마케팅 스튜디오 데이터화, 안양 대시보드 통합과 지역 확장

첫 2주의 목표는 기능 추가가 아니라, 지금 나가는 브리핑이 헤드라인·배지·숫자·문장 어느 하나도 스스로를 반박하지 않게 만드는 것이다. 이원화는 그 위에서 규칙으로 완성된다.

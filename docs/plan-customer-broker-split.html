한눈에

검토 결론

디자인 시스템, 정책 단계 7분류, 보유형태별 영향도, 컴플라이언스 문구, 멀티채널 출력은 강점입니다. 그러나 실시간 뉴스가 들어오는 순간 모든 카드의 해설이 같은 안내문 3줄로 덮여 "AI 브리핑"이 비고, 숫자는 데모값이라 헤드라인과 모순되며, 중개사에게 하는 말이 고객 발송물에 그대로 실립니다.

분리 원칙

"하나의 이슈 레코드, 두 개의 렌더링". 중개사용은 전체 이슈를 다루는 편집·실무 스튜디오, 고객용은 3~5개 이슈를 쉬운 말과 할 일, 공공데이터 바로가기로 담는 읽기 전용 레터입니다.

보도자료 분류

발표 주체·정책 단계·주제·영향 대상·지역의 5축 태그를 붙이고, 라우팅 규칙 8개(R1~R8)로 고객용에 실을지, 중개사 전용으로 둘지, 특정 동네 고객에게만 보낼지를 정합니다.

공공데이터

보도자료 수집 소스 12곳, 고객용 바로가기 22곳, 중개사용 바로가기 20곳을 URL과 함께 정리했고, 주제별로 브리핑에 자동 삽입할 링크 매핑과 API로 자동화 가능한 항목을 표시했습니다.

이 문서의 링크 표에서 ● 는 이번 검토에서 검색 결과로 URL을 확인한 사이트, ○ 는 널리 쓰이는 공식 도메인이지만 이 세션에서는 접속 검증을 하지 못한 사이트입니다.

1

현재 사이트 검토

사이트는 한 개의 HTML 파일이 데이터·렌더링·편집·공유를 모두 맡는 "중개사용 제작 스튜디오"이며, 그 미리보기 화면이 그대로 고객에게 보내지는 구조입니다.

1.1 무엇으로 만들어져 있나

  • 구성 축: 주기 3종(DAILY·WEEKLY·MONTHLY) × 출력 4종(이메일·모바일·인스타 카드·블로그 포스팅) × 액션 5종(사무소·메일·PDF 인쇄·카카오톡·링크).
  • 콘텐츠 단위: 이슈 12개 슬롯. 정식 데모 이슈 5개(금리·공급·청약·세금·통계)와 범용 주제 7개(임대차·정비사업·대출·분양·GTX·전세가율·신도시). 각 이슈는 정책 단계, 기관, 한 줄 요약, 설명, 불릿 3개, 영향 요약, 대상 태그, 관련 기사, 보유형태 7종 영향도를 가집니다.
  • 실시간 데이터: GitHub Actions가 Google News RSS를 수집해 news.json을 커밋하고, 페이지가 이를 읽어 12개 슬롯의 제목·기사·링크를 교체합니다. 캡처 기준 "실시간 뉴스 · 09.12 오후 07:45 수집".
  • 화면 순서(이메일): 마스트헤드 → 슬로건 → 오늘의 헤드라인 → 정책 카드(4·6·8개) → 뉴스 카드(8·12·12개) → 오늘의 숫자(타일 6개와 막대) → 그래서 내 부동산에는?(7행) → 공인중개사의 한마디 → 상담 CTA → 푸터(사무소·면책·광고 표시·수신거부).
  • 저장: 사무소 정보, 섹션 편집, 블로그, 인스타 구성 모두 브라우저 localStorage. 서버·계정 없음, 기기 간 동기화 없음.
  • 발송: 메일 앱 초안(mailto·Gmail), 새 창 PDF 인쇄, 카카오 공유(SDK 키 미설정이라 실제로는 클립보드 복사), 링크 복사(?t=DAILY 파라미터만 포함).
  • 저장소의 다른 자산: 안양(만안·동안) 아파트 실거래 대시보드(index.html)와 수집 스크립트(fetch.js·process.js·top10.js)가 별도로 있어, "우리 동네 숫자" 섹션의 데이터 소스로 바로 쓸 수 있습니다.

1.2 잘 만든 것 (유지)

  1. 정책 단계 7분류 — 확정 · 시행 예정 · 입법예고 · 국회 심의 중 · 정부 검토 · 언론 보도 · 전망/분석. 이 서비스에서 가장 가치 있는 편집 원칙이며, 3장의 분류 체계도 이를 확장합니다.
  2. 보유형태 7종 영향도(무주택·1주택·다주택·매수 예정·매도 예정·임대인·임차인) — 고객 세그먼트 설계의 뼈대입니다.
  3. "출처와 기준일이 확인된 수치만 게시", 면책·광고성 정보 표시·수신거부 문구 — 컴플라이언스 골격이 이미 있습니다.
  4. 한 데이터로 네 채널 생성 — 이메일, 모바일, 1080×1350 인스타 카드(테마 6종·템플릿 4종·ZIP 저장), SEO 골격을 갖춘 블로그 초안(이미지 삽입 위치, 직접 경험 입력 슬롯, 용어 풀이, 체크리스트 표).
  5. 사무소 브랜딩 자동 반영, 섹션 인라인 수정·삭제·복원, 발행일 자동 계산.
  6. 에디토리얼 디자인 시스템(네이비·골드·오렌지)과 카드 가독성. 이 톤은 고객용 레터에서 그대로 살릴 가치가 있습니다.

1.3 문제점 (심각도순)

P0 신뢰를 깨는 문제 · P1 구조 문제 · P2 마감 문제

P0

1. 실시간 모드에서 해설이 비어 있다

news.json이 들어오면 hydrateNews()가 모든 이슈의 불릿·영향 요약·페르소나 영향도를 같은 문장으로 덮어씁니다. 캡처 기준 DAILY 12개, WEEKLY 18개 카드에 "헤드라인보다 적용 대상·시행 시점·구체 수치를 원문에서 먼저 확인하세요"가 반복되고, 영향도는 전부 ●●●○○입니다. 브리핑이 아니라 기사 링크 목록이 됩니다.

해결수집 후 요약·태깅·영향도 생성 단계(LLM)와 검수 플래그를 파이프라인에 넣고, 생성 실패 시 카드를 숨깁니다.
P0

2. 숫자가 헤드라인과 모순된다

'오늘의 숫자'는 코드에 고정된 데모 상수입니다. 같은 화면에서 헤드라인은 "두 달 연속 기준금리 인상"인데 타일은 "기준금리 2.5% 보합, 기준일 2026-09-02"입니다. 한국은행 공시 기준으로는 7월 16일 2.75%, 8월 27일 3.00%입니다. 타일의 '출처' 링크도 네이버 검색으로 갑니다.

해결한국은행 ECOS, 부동산원 R-ONE, 실거래가 API(이미 fetch.js에 있음)로 타일을 채우고, 출처는 실제 통계 페이지로 연결합니다.
P0

3. 기관·단계 배지가 기사와 무관하다

배지는 주제 슬롯에 고정되어 있어 실제 기사와 어긋납니다. "대전시의회, 둔산지구 재건축…" 기사에 국토교통부, "특별공급 개편 이후 달라진 당첨 전략" 기사에 입법예고, "종부세 개편" 기사에 공식자료·언론 보도가 붙습니다. 단계 분류가 이 서비스의 핵심 약속인데 이를 스스로 깨고 있습니다.

해결배지는 이슈 레코드의 실제 메타(발표 주체·단계)에서만 렌더하고, 분류기가 확신하지 못하면 배지를 숨기고 '확인 필요'만 표시합니다.
P0

4. 중개사에게 하는 말이 고객 발송물에 실린다

불릿 "고객 상황에 따라 영향이 달라짐을 안내하세요", "확정된 내용과 논의 단계를 구분해 설명하세요"는 중개사 지침입니다. 인스타 카드의 "공인중개사 POINT ①②③" 슬라이드와 슬로건 "AI는 중개사를 대체하지 못합니다. AI를 아는 중개사가 대체합니다"도 B2B 문구입니다. 이 자료는 "광고성 정보 수신에 동의한 고객에게 발송"된다고 푸터에 적혀 있습니다.

해결렌더 함수에 audience 파라미터를 두고, 고객용에서는 금지어(R7)를 자동 차단합니다. 2장의 분리 설계가 이 문제의 답입니다.
P0

5. 공유 링크가 고객에게 '중개사 화면'을 보여준다

카카오·링크 공유 URL은 같은 스튜디오 페이지이고 사무소 정보는 URL에 실리지 않습니다. 고객 브라우저에는 저장값이 없어 기본값 "홍길동부동산", "연락처를 입력해 주세요", "카카오톡 채널 미설정"이 보이고, 첫 방문 모달 "중개사무소 정보 입력"이 뜨며(첫 방문에는 ESC·배경 클릭으로 닫히지 않음), 수정·삭제 버튼과 편집 도구까지 노출됩니다.

해결발행 시 사무소 정보를 포함한 읽기 전용 스냅샷 URL을 만들고, 편집 UI와 모달은 스튜디오에만 둡니다.
P0

6. '확인 필요' 배지가 항상 켜져 있다

모든 카드에 무조건 붙도록 코드에 고정되어 있어, 경고로서 의미를 잃었습니다.

해결원문 미확인, 단계 불명, 수치 미검증일 때만 조건부로 표시합니다.
P1

7. 정책 섹션과 뉴스 섹션이 같은 배열을 두 번 렌더한다

두 섹션 모두 ISSUES 배열을 앞에서부터 자르므로 같은 카드와 같은 관련기사 3건이 반복됩니다. WEEKLY 캡처는 세로 25,180px(2배율)로 DAILY의 1.7배입니다.

해결정책 = 정부·기관 원문(보도자료·고시), 뉴스 = 언론 보도로 역할을 나누고 같은 이슈는 한 번만 싣습니다. 고객용은 분량 상한(R8)을 둡니다.
P1

8. DAILY인데 기사 날짜가 2~4주 전이다

09.12 브리핑의 정책 카드 발표일이 08.27, 08.19, 08.01, 08.03이고, '발표일'은 첫 기사 날짜를 그대로 씁니다. 주기별 신선도 기준이 없습니다.

해결DAILY 48시간, WEEKLY 7일, MONTHLY 당월로 컷을 두고, 오래된 이슈는 "지켜볼 이슈"로 내립니다.
P1

9. "그래서 내 부동산에는?"이 첫 이슈에만 연결된다

섹션 제목 옆에 첫 이슈 제목만 표시되고, 실시간 모드에서는 값이 전부 같아 정보량이 0입니다.

해결이슈마다 영향도를 두고, 고객용에서는 고객 세그먼트에 해당하는 행만 보여줍니다.
P1

10. 원문 링크의 폴백이 네이버 검색이다

기사 URL이 없으면 "원문·관련보도 보기"와 "출처"가 검색 결과 페이지로 갑니다. 고객은 원문을 기대하고 누릅니다.

해결실제 URL이 없으면 버튼을 숨기고, 보도자료는 4장의 공식 소스 URL로 연결합니다.
P1

11. 발송 전 검증이 없다

연락처·소재지·등록번호가 비어도 발송할 수 있습니다. 푸터는 "등록번호 브랜드설정에서 입력"이라 안내하지만 입력 모달에는 등록번호 칸이 없어 채울 방법이 없습니다.

해결발행 전 체크(사무소 필수 항목, 수신거부 링크, 금지어, 빈 카드)를 통과해야 발송 버튼이 열리게 합니다.
P1

12. 편집 모드와 읽기 모드가 나뉘어 있지 않다

미리보기 안에 수정·삭제 버튼이 있고, 상단 도구막대가 항상 보입니다. 중개사는 "지금 보이는 게 고객이 볼 화면인지" 확신할 수 없습니다.

해결스튜디오(편집)와 레터(발행본)를 화면과 URL 수준에서 분리합니다.
P2

13. 텍스트 겹침 3곳

정책 카드 불릿 두 줄 겹침, 뉴스 카드의 배지와 제목 겹침, CTA 제목 겹침이 캡처에 보입니다. 전체 페이지 캡처 도구의 이어붙이기 문제일 수 있으니 실제 기기에서 확인이 필요합니다.

P2

14. 푸터·주석 글자 9.5~10.5px

50대 이상 고객이 많은 채널에서는 작습니다. 본문 최소 13px, 법적 고지 최소 12px을 권합니다.

P2

15. 인스타 카드 본문이 안내문이다

실시간 모드에서 "무슨 내용인가요?" 슬라이드가 "주요 언론이 비중 있게 다룬 이슈입니다. 아래 기사 원문에서 확인하세요"로 채워집니다. SNS 카드가 다른 곳에서 읽으라고 말하는 셈입니다.

P2

16. 블로그 초안의 마감

메타 설명 블록이 본문 안에 렌더되고, 목차에 앵커가 없으며, 실시간 모드에서는 보유형태 표가 전부 3/5입니다. 구조 자체는 좋으니 데이터만 채우면 됩니다.

P2

17. 접근성

모달에 포커스 트랩이 없고, 주기·출력 선택 버튼에 aria-pressed가 없으며, 정책 단계가 색으로만 구분되는 곳이 있습니다.

P2

18. 수신거부·개인정보처리방침이 '#' 링크다

광고성 메일은 수신거부 수단이 실제로 동작해야 합니다. 발송 인프라를 붙이는 시점에 함께 해결해야 합니다.

P2

19. EDM인데 메일을 보낼 수 없다

발송은 메일 앱 초안 열기와 PDF 첨부에 의존합니다. 수신자 목록, 발송 이력, 반응 추적이 없어 "정보를 알게 해주는 서비스"로 가려면 발송 계층이 필요합니다.

1.4 개발자용 기술 메모

  • Google News RSS는 제목·링크·짧은 요약만 주므로, 해설이 비는 문제(1번)는 데이터 소스의 한계입니다. 정부 보도자료 RSS(4.1)를 1차 소스로 두고 언론 기사는 보강 자료로 붙이는 편이 정확합니다.
  • 단일 파일을 최소 data(이슈 레코드), render-letter(고객용), render-studio(중개사용) 세 모듈로 나누고, 렌더 함수는 같은 레코드를 받아 audience에 따라 다른 필드를 씁니다.
  • 기관 색상 규칙(agencyStyle)은 '기획재정부'만 인식합니다. 최근 보도에는 '재정경제부'로 나오므로 기관 사전을 데이터로 빼서 관리해야 합니다.
  • 저장소의 fetch.js에 공공데이터포털 서비스 키가 평문으로 들어 있습니다. GitHub Actions Secrets로 옮기고 키를 재발급하는 것이 안전합니다.
  • 안양 대시보드의 주간·월간 중위가 지수와 TOP10 산출 로직은 그대로 "우리 동네 숫자" API로 재사용할 수 있습니다. 실거래 신고 기한이 30일이라 최근 두 달은 잠정치라는 주석을 고객용에도 그대로 실어야 합니다.

3.2 라우팅 규칙 R1~R8

R1

단계로 1차 결정

확정·시행 예정·통계 발표·지자체 고시는 고객용 본문 후보. 입법예고·국회 심의·정부 검토·언론 보도·전망은 고객용에서는 주 1회 "지켜볼 이슈" 코너에 한 줄로만, '확정 아님' 표시와 함께. 중개사용은 전 단계를 다룹니다.

예소득세법 시행령 개정안 입법예고(의견제출 9.10까지) → 고객 "지켜볼 이슈" 한 줄, 중개사 전문
R2

중개업 제도는 중개사 전용

공인중개사법, 중개보수, 임장비, 확인·설명 의무, 전자계약, 협회, 행정처분·과태료는 고객용에 싣지 않습니다. 시행이 확정된 뒤 고객이 체감할 변화만 한 줄로 알립니다.

예원룸·오피스텔 공동관리비 확인·설명 의무화 → 시행 시 고객용 "계약 전 관리비 내역을 요구할 수 있어요" 한 줄
R3

지자체 고시는 동네 타깃

안양시 정비구역 지정·주민공람, 특별정비구역, 지구단위계획 고시는 중개사 전용으로 전문을 싣고, 고객에게는 해당 동에 거주·보유한 수신자에게만 발송합니다.

예수촌마을(A블럭) 재개발 정비구역 지정(안) 공람(공고 제2026-1260호) → 관양동 고객 타깃
R4

세금·대출·청약은 양쪽, 깊이만 다르게

고객용은 "나에게 적용되나?" 체크 3개와 계산 바로가기(홈택스·기금e든든·청약홈). 중개사용은 요건표, 경과규정, 상담 스크립트, 세무사 연계 기준.

R5

통계는 지역 숫자로 치환

고객용은 안양 숫자 2~4개와 추세 한 줄. 서울 통계는 안양 수치로 바꾸고, 바꿀 수 없으면 싣지 않습니다. 중개사용은 전체 표와 원자료 링크, "신고 기한 30일이라 최근 두 달은 잠정치" 주석.

예"서울 평균 월세 160만 원 돌파" → 고객용에는 안양 월세 중위값·추이로
R6

언어 규칙

고객용: 2인칭 존댓말, 한 문장 30자 안팎, 용어 첫 등장 시 풀이, 지시문(~하세요)은 고객 본인의 행동에만. 중개사용: 체크리스트 명령형, 법령·조문·수치는 원문 그대로.

4.5 API로 자동화할 수 있는 것

  • 실거래가 API(공공데이터포털, 이미 fetch.js에서 사용) — 안양 만안·동안 매매·전월세를 주간·월간 중위가로 집계해 "우리 동네 숫자" 타일 4개를 채웁니다. 최근 두 달은 잠정치 표기.
  • 한국은행 ECOS API — 기준금리, 예금은행 주택담보대출 금리(신규취급액). 현재 데모 상수 두 개를 대체합니다.
  • 한국부동산원 R-ONE API — 주간 아파트 매매·전세 가격지수(경기 안양 단위), 월간 거래량, 미분양.
  • korea.kr·국토부 RSS — 보도자료 제목·본문 링크. 태깅 파이프라인의 1차 입력.
  • 경기도 보도자료 API(공공데이터포털 15034926) — 도 단위 정책 발표.
  • 건축물대장·토지 API(공공데이터포털) — 중개사용 물건 조사 자동화(노후도·위반건축물).
  • 안양시 고시공고 — API가 없어 HTML 수집이 필요합니다. 제목에서 동·구역명을 뽑아 E축 태그로 씁니다.

화면 구성과 UX 백로그

5.1 화면 구성안

중개사용 STUDIO

  1. 인박스 — 수집된 보도자료·기사·고시 목록. 열: 시각, 주체, 단계 배지, 주제, 지역, 추천 등급(★ 발송 권장 · ◎ 참고 · ○ 보관), 중복 묶음. 필터: 오늘·이번 주, 안양만, 확정만, 미검수만.
  2. 이슈 상세 — 팩트시트 → 원문·법령·관련 기사 → 지역 영향 → 상담 스크립트 → 실무 체크리스트 → FAQ → 세그먼트 영향도 → [고객용 미리보기] 토글.
  3. 레터 빌더 — 세그먼트 선택 → 규칙 R1~R8로 자동 선정 → 카드 순서·코멘트 편집 → 우리 동네 숫자 자동 → 발행 전 검증(필수 사무소 정보, 수신거부 링크, 금지어, 빈 카드) → 이메일·모바일 미리보기 → 발행(읽기 전용 URL) → 발송.
  4. 마케팅 스튜디오 — 현재 인스타 카드·블로그 기능 이관. 본문 슬라이드는 고객용 필드(what_changes_for_me, actions)로 채우고 금지어 규칙을 동일 적용.
  5. 데이터 — 저장소의 안양 대시보드 통합(주간·월간 중위가 지수, TOP10) + 4.3의 바로가기 패널.
  6. 설정 — 사무소(등록번호 포함), 채널(카카오 채널·발신 메일), 수신자 목록과 세그먼트·동 태그, 서명·한마디 기본 문구.

고객용 LETTER

  1. 마스트헤드 — 사무소명·대표·등록번호(신뢰 요소). 슬로건은 고객 문구로 교체, 예: "안양 부동산 소식, 3분 브리핑".
  2. 오늘의 한 줄 — 가장 중요한 이슈의 고객용 제목.
  3. 이슈 카드 3~5 — [주체·단계·날짜] 쉬운 제목 → 무슨 일(2문장) → 나에게는(세그먼트 1문장과 영향도) → 지금 할 일(1~3) → 원문·바로가기.
  4. 우리 동네 숫자 — 안양 만안·동안 타일 4개와 6개월 추세, 출처·기준일, 잠정치 표시.
  5. 지켜볼 이슈 — 주 1회, 확정 전 사안 한 줄씩, '확정 아님' 표시.
  6. 용어 하나 — 이번 호 이슈와 연결된 용어 1개.
  7. 중개사의 한마디 — 사진·이름·한 문단. 비어 있으면 섹션 제거.
  8. 상담 CTA — 전화·카카오 채널·예약. 미설정 채널은 버튼 자체를 숨김.
  9. 푸터 — 사무소·등록번호·면책·광고성 정보 표시·실제로 동작하는 수신거부 링크. 글자 12px 이상.

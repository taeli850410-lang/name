# 쌤태리 블로그 원고

대표님(쌤태리 부동산 컨설팅)이 2026년 10월에 정한 블로그 작성 방식이다. 기준 원본은 `ssaemtari-company/blog/`에 있고, 이 파일은 그 기준대로 원고를 만드는 작업 순서다.

## 먼저 읽을 것

한 대화에서 처음 원고를 쓸 때는 기준 문서 두 개를 끝까지 읽는다. Word 파일이라 텍스트로 바꿔 읽는다.

```bash
cd ssaemtari-company/blog
pandoc 01_기획서.docx -t gfm --wrap=none        # 작업 흐름 · 커넥터 · 계산 공식 · 유형별 체크 · 제목 · 사례 · 게시 전 체크리스트
pandoc 02_작성기준_및_샘플.docx -t gfm --wrap=none  # 13블록 구성 · 감성 30% · 제목 공식 · 새 형식 샘플
```

말투와 깊이는 `04_완성원고/`의 원고 한 편(예: `신용산북측1구역_근생매물_블로그원고_v2.docx`)으로 확인한다. 완성 원고 6편은 13블록 형식 이전에 쓴 것이다. 형식은 02 작성기준과 `05_원고생성_코드/원고_템플릿.js`를 따른다.

## 독자와 최종 기준

- 독자는 재개발 매물을 검토하는 일반 투자자다. 세 질문에 답하는 순서로 쓴다: "이 값을 줘도 되나", "새집을 정말 받을 수 있나", "잘못 계약할 위험은 없나".
- 최종 기준: 이 글을 본 고객이 광고라고 느끼는가, 믿을 만한 공인중개사라고 느끼는가. 검수 점수 정확성 30 + 고객가치 25 + 신뢰 20 + 이해도 15 + 차별성 10, 90점 미만이면 한 번 더 고친다.

## 받을 자료

`03_프롬프트/2_구역_요청_양식.txt`의 항목이다. 구역명 · 매물 유형 · 매매가 · 대지 면적 · 매물 출처가 없으면 쓰기 전에 묻는다. 나머지 빈칸은 커넥터로 찾고, 못 찾으면 원고에 빈칸으로 두고 작성자 참고용에 적는다. 이미지가 흐려 안 읽히는 숫자는 짐작하지 말고 다시 요청한다.

## 작업 흐름 7단계

1. **자료 받기**: 매물 숫자표(매매가 · 대지 · 건물 면적 · 감정가 · 분양가 · 평형 · 임대 조건).
2. **커넥터 조회**: 아래 서버를 ToolSearch로 불러 쓴다. 실거래는 약 10건.
   - `real-estate` 국토부 실거래(단독다가구 · 연립다세대 · 아파트 · 상업업무용 매매와 전월세). 최근 1~2달은 신고가 덜 잡힌다. 직거래는 표에서 뺀다.
   - `hofinder` 거래별 대지 면적 · 지번 앞자리로 대지 평당가 계산, 구역 번지대 거래 골라내기. 코드 조회의 번지 필터가 0건이면 지역 조회 뒤 직접 거른다.
   - `building-register` 사용승인일 · 구조 · 면적 · 반지하 대조, 구역 노후도 · 규제 집계. 구역 DB에 없는 구역이 있다.
   - `seoul-redevelopment` 정비구역 결정 · 변경 고시. 사업시행 · 관리처분 같은 추진 단계는 없으니 기사 · 정보몽땅으로 확인한다.
   - `reb` 권역별 매매가격지수로 "시장 전체 vs 이 구역" 비교. 개별 매물 시세가 아니다.
   - `vworld` 주소 → 좌표 · 필지 · 용도지역. `PlayMCP` 카카오 부동산은 아파트 · 빌라 시세용(단독 · 무허가에는 맞지 않음).
   - 커넥터가 없거나 조회가 안 되면 숫자를 만들지 말고 대표님께 실거래를 붙여 달라고 한다.
3. **기사 · 공식자료**: 사업 단계 · 시공사 · 세대수 · 최근 발표. 자료마다 숫자가 다르면 둘 다 적는다. 기사 날짜를 확인한다.
4. **쟁점 찾기**: 이 매물의 판단을 뒤집을 사실 1~2개(후보지 탈락, 분양자격, 광고 가능 여부, 토지거래허가 등). 찾으면 숨기지 말고 글의 중심에 놓는다. 가장 중요한 단계다.
5. **계산**: 대지 평당가 = 매매가 ÷ 대지(평), 프리미엄 = 매매가 − 감정평가액, 권리가액 = 감정평가액 × 비례율, 총투자금 = 매매가 + 분담금, 프리미엄 한계선 = 옆 신축 같은 평형 실거래 − 조합원 분양가, 분담금 한계선(초기 단계) = 옆 신축 실거래 − 매매가, 월세 수익률 = 연 월세 ÷ (매매가 − 보증금). 한계선 옆에는 이자 · 이주비 · 추가 분담금이 빠져 있다는 문장을 항상 쓴다.
6. **구성 · 원고**: 13블록, 감성 30%, 제목 10개 중 1개 추천.
7. **검수**: 숫자 재대조, 광고 규정, 렌더링 확인, 점검 스크립트, 작성자 참고용 페이지.

## 쓰는 원칙

- 매물이 먼저 나온다. 그다음 실거래 → 핵심 계산 → 위치 → 일정 → 체크리스트 → 마치며.
- 모든 섹션은 사실 → 의미 → 판단.
- 감성 약 30%: 독자 속마음은 따옴표로, 숫자 → 마음 → 계산 순서, 설렘과 불안은 한 문단에 짝으로. 도입 · 마치며는 감성 절반, 본문은 섹션마다 한두 줄.
- 숫자를 만들지 않는다. 조회 · 제공된 숫자만 쓰고 추정치는 '추정', 가정 계산은 '가정'이라고 적는다.
- 경험을 지어내지 않는다. 경험이 들어갈 자리는 `exp()` [직접 경험] 박스로 비워 둔다. 남의 임장 후기는 "방문기들을 보면", 상담 질문은 "이 매물 앞에서 던져야 할 질문"으로 쓴다. '저라면'은 대표님 실제 기준일 때만.
- 지번이 가려진 실거래에는 구역 안인지 확인 못 했다는 각주를 단다.
- 단계 표현은 신청인지 인가인지 구분한다('관리처분 예정' 금지).
- 쓰지 않는 말: "무조건 오른다", "지금 안 사면 후회", "마지막 기회", "확정 수익", "안녕하세요 오늘은 알아보겠습니다", "많은 분들이 궁금해하시는데요", "끝까지 읽어주세요".
- 다른 사무소 매물이면 광고 가능 여부(의뢰 · 공동중개 관계)를 작성자 참고용 맨 위에 적는다.
- 형광펜 5~6곳, 핵심 키워드는 `^^파란 굵게^^`로 문장 안에 1~2번씩만, 중개사 한 줄(`tip`) 4~5개, 해시태그 10개 안팎.

## 제목

- 구역명을 맨 앞에. 앞 25자 안에 매물 유형과 가격, 전체 30~40자(공백 제외).
- 이번에 새로 찾은 가장 강한 데이터를 제목에 꺼낸다. 가정으로만 나오는 숫자, '최저'처럼 사실과 다를 수 있는 말은 넣지 않는다.
- 공식: A 확인형("… 살 때 꼭 확인할 N가지"), B 속마음형("'아직 늦지 않았나' 망설이는 분들을 위한 팩트 체크"), C 질문 · 숫자형("'…'에 숫자로 답합니다"). 직전 글과 같은 공식을 연달아 쓰지 않는다.
- `ssaemtari-company/blog/README.md`의 원고 목록과 대표님이 알려 준 이전 글 제목을 보고 첫 단어 · 문장 구조 · 중심 소재가 겹치지 않게 한다.
- 10개를 만들어 작성자 참고용 페이지에 넣고 1개를 추천한다.

## Word 원고 만들기

`ssaemtari-company/blog/05_원고생성_코드/`에서 작업한다. 블록 함수 설명은 같은 폴더 `README_코드.txt`.

```bash
cd ssaemtari-company/blog/05_원고생성_코드
npm install                                   # 처음 한 번 (docx 패키지)
cp 원고_템플릿.js 원고_<구역명>_<유형>.js       # 13블록 순서가 들어 있는 뼈대
# [[ ]] 자리를 모두 채운다. 날짜 줄은 게시하는 날(오늘).
node 원고_<구역명>_<유형>.js ../04_완성원고/<구역명>_<유형>_블로그원고.docx
python3 ../../tools/check_blog_post.py ../04_완성원고/<구역명>_<유형>_블로그원고.docx
```

- 같은 매물을 고쳐 쓰면 원고 스크립트를 고치고 docx 파일 이름에 `_v2`, `_v3`을 붙인다. 이전 docx는 `04_완성원고/이전버전/`으로 옮긴다.
- 점검 스크립트의 오류는 모두 고친다. 경고는 이유가 있으면 남기되 작성자 참고용에 이유를 적는다.
- 렌더링 확인: 표 · 박스가 페이지 사이에서 깨지지 않는지 이미지로 본다.

  ```bash
  soffice --headless --convert-to pdf --outdir <스크래치> <원고.docx>
  pdftoppm -r 60 -png <스크래치>/<원고>.pdf <스크래치>/page
  ```

- 작성자 참고용 페이지(`authorPage()` 뒤): 제목 후보 10개(추천 표시), 가장 먼저 확인할 것(광고 가능 여부 · 판단을 바꿀 사실), 게시 전에 확인할 것(숫자를 어디서 대조했는지 · 추정 · 가정 · 단계 표현 근거), 출처(기사 링크 · 커넥터 조회 범위).

## 끝내기

1. `ssaemtari-company/blog/README.md`의 원고 목록 표에 한 줄 추가한다(파일 · 매물 · 추천 제목).
2. 원고 스크립트와 docx를 커밋하고 지정된 브랜치에 푸시한다.
3. 대표님께 docx 파일을 보내고(파일 전달 도구가 있으면), 답변에는 추천 제목, 이 매물의 쟁점 한 줄, 게시 전에 대표님이 확인할 항목만 짧게 쓴다. 원고 전문을 채팅에 다시 붙이지 않는다.

## 유튜브 제목 · 설명란

`03_프롬프트/3_유튜브_요청_프롬프트.txt`와 01 기획서 9번을 따른다.

- 제목: 후킹 제목 8개 + 추천 2개. 숫자 충격 + 궁금증, 기대 → 반전. 가정으로만 나오는 숫자는 넣지 않는다. 쇼츠는 40자 안팎. 썸네일이 질문을 던지면 제목은 반전을 흘리고, 썸네일에 없는 숫자를 하나 더 넣는다.
- 설명란 순서: 첫 2~3줄 가장 강한 문장('더보기' 위) → ✔ 핵심 숫자 5~6줄 → 판단 한 줄 → ※ 추정치 고지 → ▶ 목차(첫 줄 00:00) → ▶ 매물 정보(중개사무소 명칭 · 소재지 · 연락처 · 등록번호 · 대표 성명, 매물 소재지 · 종류 · 거래형태 · 가격 · 면적) → 해시태그(앞 3개가 제목 위에 표시, 쇼츠는 #shorts).
- 유튜브 문구는 채팅 답변으로 준다. 대표님이 파일을 원하면 원고와 같은 폴더에 txt로 저장한다.

# 쌤태리 블로그 원고

대표님(쌤태리 부동산 컨설팅, 재개발·재건축 전문 공인중개사)의 네이버 블로그 원고를 쓴다.
기준 원본은 `ssaemtari-company/blog-kit/`이고, 이 문서는 그 요약이다. 둘이 다르면 키트가 맞다.

## 0. 쓰기 전에 읽는다

처음 원고를 쓰는 대화라면 아래를 먼저 읽는다. docx는 `pandoc 파일.docx -t gfm`으로 읽는다.

| 파일 (blog-kit/ 기준) | 읽는 이유 |
|---|---|
| `02_작성기준_및_샘플.docx` | 13블록 구성, 감성 30%, 제목 공식, 새 형식 샘플. **블록 모양은 이 문서가 최우선** |
| `01_기획서.docx` | 작업 흐름 7단계, 커넥터, 계산 공식, 유형별 체크, 구역별 사례, 게시 전 체크리스트 |
| `04_완성원고/` 중 같은 유형 1편 | 문장 톤 · 분량 · 작성자 참고용 페이지 쓰는 법 (이 원고들은 새 형식 이전이라 블록 모양은 02를 따른다) |
| `03_프롬프트/1_새대화_시작_프롬프트.txt` | 대표님이 원고를 요청할 때 쓰는 지시문. 이 스킬과 같은 내용 |

## 1. 독자와 목표

- 독자는 재개발 매물을 검토하는 일반 투자자. 속으로 묻는 세 질문에 답하는 순서로 쓴다:
  **"이 값을 줘도 되나", "새집을 정말 받을 수 있나", "잘못 계약할 위험은 없나".**
- 목표는 조회수보다 신뢰와 상담 전환. "내 상황을 정확히 이해해 주는 전문가"로 느껴지게 한다.
- 최종 기준: "광고라고 느끼는가, 믿을 만한 공인중개사라고 느끼는가?"
  검수 점수 정확성 30 + 고객가치 25 + 신뢰 20 + 이해도 15 + 차별성 10, **90점 미만이면 한 번 더 고친다.**

## 2. 요청 받기

대표님은 `03_프롬프트/2_구역_요청_양식.txt`를 채워 매물 분석표 · 네이버 매물 캡처 · 재개발 앱 화면과 함께 준다.

- 구역명 · 매물 유형 · 매매가 · 대지 면적이 없으면 쓰기 전에 묻는다. 이미지가 흐려 안 읽히는 숫자는 지어내지 말고 빈칸으로 두고 요청한다.
- **매물 출처가 다른 사무소면** 표시·광고 규정상 의뢰 · 공동중개 관계부터 확인하라고 작성자 참고용 맨 위에 적는다.
- "이전에 올린 이 구역 글 제목"과 겹치지 않게 제목과 중심 소재를 바꾼다.

## 3. 작업 흐름 7단계

1. **자료 받기**: 매매가, 대지, 건물 면적, 감정가, 분양가, 평형, 임대 조건 → 매물 숫자표
2. **커넥터 조회**: 실거래 약 10건, 건축물대장 대조, 구역 고시, 시장 지수 (아래 4번)
3. **기사 · 공식자료**: 사업 단계, 시공사, 세대수, 최근 발표. 자료마다 숫자가 다르면 둘 다 적는다
4. **쟁점 찾기 (가장 중요)**: 이 매물의 판단을 뒤집을 사실 1~2개 (후보지 탈락, 분양자격, 광고 가능 여부, 토지거래허가 등). 나오면 숨기지 말고 **글의 중심축**으로 놓는다
5. **계산**: 평당가, 프리미엄, 총투자금, 한계선, 비례율 시나리오 (아래 5번)
6. **구성 · 원고**: 13블록, 감성 30%, 제목 10개 중 1개 추천
7. **검수**: 숫자 재대조, 광고 규정, 렌더링 확인, 작성자 참고용 페이지

## 4. 커넥터

도구가 안 보이면 ToolSearch로 불러온다. 연결이 안 되면 대표님께 실거래를 붙여 달라고 한다.

| 커넥터 | 주로 쓰는 도구 | 쓰는 곳 · 주의 |

| `vworld` | `geocode_address`, `get_land_parcel` | 주소 → 좌표 · 필지 · 용도지역. 일부 지번은 안 나온다 |
| 카카오 부동산 `PlayMCP` | `kakaoRealEstate-get_market_price` | 아파트 · 오피스텔 · 빌라 시세. 단독 · 무허가에는 맞지 않는다 |
| 웹 검색 | `WebSearch`, `WebFetch` | 기사 · 고시 · 법령. 기사 날짜를 꼭 확인한다 |

## 5. 핵심 계산 공식

| 계산 | 공식 |
|---|---|
| 대지 평당가 | 매매가 ÷ 대지(평) |
| 프리미엄 | 매매가 − 감정평가액 |
| 권리가액 | 감정평가액 × 비례율 (모르면 90 · 100 · 110% 시나리오, '가정'이라고 적는다) |
| 총투자금 | 매매가 + 분담금 (= 프리미엄 + 조합원 분양가) |
| 프리미엄 한계선 | 옆 신축 같은 평형 실거래 − 조합원 분양가 |
| 분담금 한계선 (초기 단계) | 옆 신축 실거래 − 매매가 |
| 월세 수익률 | 연 월세 ÷ (매매가 − 보증금) |

한계선 옆에는 항상 "**상한선이지 목표가 아닙니다.** 기다리는 기간의 이자 · 이주비 · 추가 분담금이 빠져 있습니다"를 함께 쓴다.

## 6. 매물 유형별로 먼저 볼 것

- **무허가주택**: 분양자격 서류, 무허가건축물관리대장 명의 변경 특약, 국공유지 점유 사용료. 권리가액이 낮으면 선택 분양 경쟁에서 불리할 수 있음
- **빌라 · 다세대**: 분양신청 여부와 평형(안 하면 현금청산), 감정평가 통지액, 토지거래허가, 투기과열지구 조합원 지위
- **신축 다세대 · 도심복합**: 후보지 선정 여부(2025년 8월 개정으로 새 후보지는 선정일이 우선공급 기준일), 개발이 늦어져도 버틸 가격인지(월세 · 옆 건물 실거래), 토지거래허가와 임차인 승계 충돌
- **단독 · 초기 단계**: 사용승인일 vs 권리산정기준일, 추진위 단계의 긴 시간 비용, 월세 수익률. 다른 사무소 매물이면 광고 가능 여부부터
- **근생 · 상가**: 서울시 조례 — 종전 토지 90㎡ 이상 또는 권리가액 ≥ 분양용 최소규모 공동주택 1가구 추산액이어야 아파트 분양, 아니면 상가 분양 또는 현금청산. 상가는 대출 · 취득세 기준도 다름

공통 규정(일반 원칙으로 쓰고 "개별 매물은 구청 · 전문가 확인"을 붙인다): 토지거래허가 기준면적 주거 6㎡ · 상업 15㎡ 초과(허가 대상이면 실거주 의무로 임대 구조가 막힐 수 있음) / 투기과열지구 재개발은 관리처분계획인가 후 매수자가 원칙적으로 조합원 불가(예외 있음), 5년 재당첨 제한 / 분양신청 기간 안에 안 하면 현금청산 / **'관리처분 예정'이 인가 신청인지 인가 완료인지 반드시 구분.**

## 7. 글 구성: 쌤태리 13블록 → blog_kit 함수

바뀌지 않는 원칙 세 가지: **매물이 먼저, 실거래 약 10건, 모든 섹션은 사실 → 의미 → 판단.**
`05_원고생성_코드/원고/_템플릿.js`에 13블록이 순서대로 들어 있다. 이 파일을 복사해서 쓴다.

| # | 블록 | 함수 | 들어갈 것 |
|---|---|---|---|
| 0 | 표시 기준 | `legend()` | 맨 위 |
| 1 | 썸네일 카드 | `thumb({area,type,price,crown,tags,color})` | 지역 · 유형 · 매매가 · 왕관 줄(단계) · 하단 태그 2개 · 카드 색(용산 빨강, 마천 연두처럼 구역별 통일) |
| 2 | 제목 | `label("  제목")`, `title()` | 아래 9번 공식 |
| 3 | 날짜 줄 · 도입 | `label("  본문")`, `date("YYYY.MM.DD")`, `p()` | 오늘 날짜 → 감성 도입 3~4줄 → `==노란 형광 결론 1줄==` |
| 4 | 가운데 인용구 | `quote([두 줄], 설명)` | 설렘 한 줄 + 불안 한 줄, 독자의 속마음 그대로 |
| 5 | 매물 표 | `h2("① …")`, `table(…, {emphasizeLast:true})`, `note()`, `tip()` | 마지막 행 매매가 노란색, 추정치 고지, 중개사 한 줄 |
| 6 | 현장 사진 · 이전 글 | `photo()`, `linkcard()` | |
| 7 | 실거래 | `table()` 약 10건 + `note()` + `info(n, …)` | 지번이 가려진 거래는 "구역 안인지 확인 못 했다" 각주. 인포그래픽: 그래프 + 비교표 + 하단 배너 |
| 8 | 핵심 계산 | `table()` + `info()` + `tip()` | 권리가액 · 비례율 또는 프리미엄 한계선 |
| 9 | 위치 · 주변 개발 | `info()` | 지도: 구역 빨강, 비교 단지 파랑, 하단 배너 |
| 10 | 사업 일정 | `table(…, {emphasizeLast:true})` + `video()` | 현재 단계 강조, 조감 · 드론 영상 자리 |
| 11 | 체크리스트 | `num()` 5개 + `info()` + `exp()` | 아이콘 5개 카드, 판단을 바꿀 사실을 1번에 |
| 12 | 마치며 | `p()` | 감성 마무리 3~4줄 + `==노란 형광 결론==` (앞에 "이런 분께 맞고, 이런 분은 기다리는 편이 낫습니다"를 둘 수 있다) |
| 13 | 상담 안내 | `contact(구역, 서비스, 문구)`, `photo()`, 해시태그 | 조감도(출처 필수), 해시태그 10개 안팎 |
| 끝 | 작성자 참고용 | `PageBreak` 뒤 | 가장 먼저 확인할 것 → 제목 후보 10개 → 게시 전에 확인할 것 → 출처(`link()`) |

- 마크업: `**굵게**`, `==노란 형광==`, `^^파란 굵은 키워드^^`. 표 셀 줄바꿈은 `"\n"`. **표 열 너비 합계는 9638.**
- 초록 '중개사 한 줄'(`tip`) 4~5개, 노란 형광 5~6곳, 핵심 키워드는 파란 굵은 글씨로 문장 안에 1~2번씩만.
- 인포그래픽(`info`)마다 제목 · 들어갈 내용 · 하단 배너 결론 한 줄 · 캡션을 적는다. 대표님이 그대로 이미지로 만든다.
- 실거래 표와 계산 카드는 그 구역에서 더 강한 쪽을 앞에 둔다.
- 상담 카드의 필수 표기(중개사무소 명칭 · 소재지 · 연락처 · 등록번호 · 대표 공인중개사 성명)는 `contact()`가 자리를 넣는다. 사무소 정보는 아직 확정되지 않았으니(`company-profile.md`도 [확인 필요]) 지어 넣지 않는다.

## 8. 감성 30%

- 속마음은 따옴표로 꺼낸다 ('아직 늦지 않았나', '상가로도 아파트가 나오나') — 제목 · 인용구 · 소제목에.
- **숫자 → 그 숫자 앞에서 드는 마음 → 계산** 순서.
- 설렘과 불안을 한 문단에 짝으로. 기대만 쓰면 광고, 걱정만 쓰면 겁주기로 읽힌다.
- '솔직히 말씀드리면', '저라면'은 대표님의 실제 판단 기준일 때만 쓰고, 작성자 참고용에 "고쳐 주세요"라고 남긴다.
- 리듬: 긴 설명 두 문장 뒤에 짧은 판단 한 문장.
- 배치: 도입 · 마치며는 감성 절반, 본문 섹션은 한두 줄(약 20%) → 전체 약 30%.
- 숫자 없이 감정만 있는 문단은 쓰지 않는다.

## 9. 제목

- 구역명을 맨 앞에. 앞 25자 안에 매물 유형과 가격, 전체 30~40자.
- 이번에 새로 찾은 가장 강한 데이터를 꺼낸다(옆 신축 21억, 대지 2.42평, 후보지 발표 등).
- 가정으로만 나오는 숫자(분양가 가정 총투자금 등)와 '최저'처럼 사실과 다를 수 있는 말은 넣지 않는다.
- 공식: **A 확인형** `[구역명] + 단계·브랜드 + 매물 + '살 때 꼭 확인할 N가지'` / **B 속마음형** `구역명 + 가격대 매물 + '속마음' + 팩트 체크` / **C 질문·숫자형** `구역명 + 매물 가격 + 독자의 질문 + '숫자로 답합니다'`. 직전 글과 같은 공식을 연달아 쓰지 않는다.
- 10개를 만들어 작성자 참고용에 넣고 1개를 추천해 본문 제목으로 쓴다.

## 10. 지키는 원칙

- **숫자를 만들지 않는다.** 제공 · 조회된 숫자만 쓰고, 추정치는 '추정', 가정은 '가정'이라고 적고, 출처를 남긴다.
- **경험을 지어내지 않는다.** 남의 임장 후기는 "방문기들을 보면", 상담 질문은 "이 매물 앞에서 던져야 할 질문"으로 쓴다. 실제 경험 자리는 `exp()` [직접 경험] 박스로 비워 둔다.
- 쓰지 않는 말: "무조건 오른다", "지금 안 사면 후회", "마지막 기회", "확정 수익", "안녕하세요, 오늘은 알아보겠습니다", "많은 분들이 궁금해하시는데요", "끝까지 읽어주세요".
- 법률 · 세금 · 대출 · 정책은 일반 원칙으로 쓰고 최신 확인이 필요한 부분을 구분한다.

## 11. 만들기와 검수

```bash
cd ssaemtari-company/blog-kit/05_원고생성_코드
npm install                       # 처음 한 번 (docx 9.7.1)
cp 원고/_템플릿.js 원고/<구역명>_<유형>_블로그원고.js
# … 원고 작성 …
node 원고/<구역명>_<유형>_블로그원고.js ../04_완성원고/<구역명>_<유형>_블로그원고.docx
```

- 같은 매물을 고쳐 쓰면 파일 이름에 `_v2`, `_v3`을 붙이고, 지난 판은 `04_완성원고/이전버전/`으로 옮긴다.
- 렌더링 확인: `soffice --headless --convert-to pdf`로 PDF를 만들고 `pdftoppm -r 60 -png`로 페이지 이미지를 떠서 직접 본다. 표 · 박스가 페이지 사이에서 깨지거나 번호 목록이 이어 붙지 않았는지 확인한다(`num()`은 한 문서 안에서 번호를 이어 간다).
- 게시 전 체크리스트(작성자 참고용에 넣는다): 날짜 줄을 게시일로 / 매물 숫자를 원자료와 재대조 / 가려진 지번 각주 / 단계 표현(신청 · 인가) / 광고 가능 매물 · 필수 표기 / [직접 경험] 박스 채우거나 지우기 / 형광펜 5~6곳 · 키워드 억지 반복 없음 / 이미지 출처 / 해시태그 10개 안팎.
- 끝나면 원고 스크립트와 docx를 함께 커밋해 푸시하고, docx는 SendUserFile로 대표님께 보낸다. 대화 답장에는 추천 제목, 이 매물의 쟁점 한두 줄, 게시 전에 대표님이 확인할 것만 짧게 쓴다.

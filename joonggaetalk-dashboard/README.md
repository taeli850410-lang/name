# 부동산TALK 대시보드 프로토타입

공인중개사용 CRM **부동산TALK**의 화면을 사용자군별로 다시 설계한 Next.js 프로토타입입니다.
UX 검토 보고서에서 지적한 항목(내비게이션·오늘 할 일·위험 행동 분리·실패 사유 문장화·용어 통일 등)을 실제 화면으로 옮겼습니다.

- 기술: Next.js 15 (App Router) · React 19 · TypeScript · 의존성 없는 순수 CSS
- 데이터: 전부 예시(목업)이며 `src/data/*.ts` 안에 있습니다. 기준일은 **2026-09-12(토)** 로 고정되어 있습니다 (`src/lib/format.ts`의 `TODAY`).
- 저장: 화면에서 등록·수정·삭제하면 브라우저 메모리에만 반영됩니다(새로고침하면 초기화).

## 실행

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # 타입 검사 포함 프로덕션 빌드
npm start
```

Node.js 18.18 이상이 필요합니다.

## Vercel 배포

라이브: **https://joonggaetalk-dashboard.vercel.app**

프로젝트 `joonggaetalk-dashboard` 가 `taeli850410-lang/name` 에 연결돼 있습니다.

### 지금은 부트스트랩으로 배포합니다

이 저장소는 최상단에 다른 프로젝트(`index.html` 외)가 있고 이 앱은
`joonggaetalk-dashboard/` 안에 있습니다. Vercel 의 **Root Directory** 가
비어 있으면 최상단에서 `next build` 를 돌려 이렇게 끝납니다.

```
[Error: > Couldn't find any `pages` or `app` directory. Please create one under the project root]
```

클론도 의존성 설치도 다 성공한 뒤 마지막에 터지기 때문에 코드 문제로 오해하기 쉽습니다.
**Root Directory 가 설정되기 전까지 `main` 푸시는 자동 배포되지 않고 실패합니다.**

그동안은 `deploy/` 의 부트스트랩 두 파일만 올려 배포합니다. 올린 파일이 곧 빌드 루트라
Root Directory 설정과 무관하고, 빌드할 때 GitHub 에서 소스를 받아 옵니다.

```bash
cd joonggaetalk-dashboard/deploy
npx vercel --prod            # 또는 파일 업로드형 도구로 이 두 파일만 배포
```

브랜치·폴더는 `SOURCE_REPO` · `SOURCE_BRANCH` · `SOURCE_DIR` 로 바꿉니다 (기본값 `main`).

### 자동 배포로 바꾸려면

**Settings → General → Root Directory** 에 `joonggaetalk-dashboard` 를 넣으면
그때부터 `main` 푸시마다 자동 배포됩니다. 부트스트랩은 더 쓰지 않아도 됩니다.

### 저장소를 거치지 않고 올리고 싶을 때

```bash
cd joonggaetalk-dashboard
npx vercel --prod      # 이 폴더에서 실행하므로 Root Directory 설정과 무관합니다
```

### 환경 변수

Settings → Environment Variables 에 넣습니다. 하나도 없어도 앱은 뜨고,
각 연동 화면이 "설정되지 않음"과 발급 방법을 안내합니다.

| 연동 | 변수 |
|---|---|
| 건축물대장 | `DATA_GO_KR_API_KEY` |
| 주소·필지 (VWorld) | `VWORLD_API_KEY`, `VWORLD_REFERER` |
| 정기결제 | `PORTONE_API_SECRET` + `PORTONE_WEBHOOK_SECRET`, 또는 `TOSS_SECRET_KEY` |
| 첨부 파일 | `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` |

`VWORLD_REFERER` 는 VWorld 에 등록한 서비스 URL 과 **글자 그대로 같아야** 합니다.
키가 맞아도 도메인이 다르면 거절됩니다.

## 외부 연동 — 건축물대장 (국토교통부)

물건 등록·상세에서 **[대장 조회]** 를 누르면 국토교통부 건축물대장의 면적·주용도·구조·층수·세대수·사용승인일·내진능력을 그대로 가져옵니다. 프로토타입의 다른 데이터와 달리 이 부분은 **실제 오픈API 호출**입니다.

### 켜는 방법

1. [공공데이터포털](https://www.data.go.kr)에서 **건축물대장정보 서비스** 활용 신청 (승인 1~2일)
2. 마이페이지 › 오픈API › 인증키에서 **일반 인증키(Decoding)** 복사
3. 로컬은 `.env.local`, Vercel은 Settings › Environment Variables 에 아래 이름으로 등록

```bash
DATA_GO_KR_API_KEY=발급받은_일반_인증키
```

키를 넣지 않아도 화면은 동작합니다. `[예시 응답 보기]`를 누르면 실제로 받아 둔 응답 한 건(인천 십정동 630, 더샵 부평센트럴시티)을 같은 코드로 정규화해 보여 주며, 화면에 **예시** 배지가 붙습니다.

### 동작 방식

```
주소 검색(다음 우편번호) → 법정동코드 10자리 + 지번주소
        ↓  bcode 앞5 = 시군구코드, 뒤5 = 법정동코드 / 지번 → 번·지 4자리
POST /api/building-register  (인증키는 서버에만, 브라우저로 내려가지 않음)
        ↓
getBrTitleInfo(표제부) → 동 목록 → 사용자가 동 선택 → 폼에 반영
```

| 파일 | 역할 |
|---|---|
| `src/lib/bldrgst.ts` | 번·지 파싱, 응답 정규화, 동 매칭, 오류 문구. 의존성 없는 순수 함수 |
| `src/app/api/building-register/route.ts` | 국토부 API 프록시. `GET` 키 설정 여부 · `GET ?demo=1` 예시 · `POST` 조회 |
| `src/lib/daumPostcode.ts` | 다음 우편번호 스크립트 로더 (키 불필요) |
| `src/components/property/RegisterLookup.tsx` | 조회 버튼 · 동 선택 · 요약 카드 · 반영 |
| `src/data/brSample.ts` | 실제로 받아 둔 응답 한 건 (테스트 입력이자 예시 화면 데이터) |

### 값을 다룰 때 지킨 것

- **집합건물(아파트·오피스텔)의 연면적은 폼의 면적에 채우지 않습니다.** 대장의 연면적은 동 전체 면적이라 개별 호의 전용면적이 아닙니다. 화면에 그 이유를 적고 등기부 확인을 안내합니다.
- **주차 0은 '주차 없음'으로 쓰지 않습니다.** 단지형 아파트는 표제부 주차란이 비어 있고 총괄표제부에 실립니다. 산출할 수 없으면 비워 두고 "대장에 기재 없음"으로 표시합니다.
- **부속건축물은 동 후보에서 뺍니다.** 주민공동시설·경비동이 아파트 동으로 잡히지 않습니다.
- **오류는 원인 한 줄 + 지금 할 수 있는 일로 씁니다.** 인증키 미설정, 활용 신청 누락, 일일 한도 초과, 대장 없음, 서버 무응답을 각각 다른 문구로 안내합니다 (`REGISTER_ERRORS`).
- **Encoding 키를 넣어도 동작합니다.** 포털이 주는 두 가지 키 중 Encoding 키는 이미 퍼센트 인코딩되어 있어 그대로 쓰면 이중 인코딩으로 인증에 실패합니다. 서버가 한 번 풀어서 씁니다.

### 테스트

```bash
npm test    # 실제 응답으로 정규화 로직 검증 (12개)
```

## 외부 연동 — 주소·필지 (VWorld)

물건 등록·상세의 **[필지 조회]** 는 주소를 좌표와 지번으로 바꾸고 **지목·용도지역·개별공시지가**를 확인합니다. 건축물대장이 건물을 맡는다면 이쪽은 땅을 맡습니다 — 나대지·토지 물건에는 대장이 아예 없기 때문에 이 조회가 유일한 공부 정보입니다.

### 켜는 방법

1. [vworld.kr](https://www.vworld.kr) 회원가입 → 오픈API → 인증키 발급 (당일)
2. 발급할 때 **서비스 URL** 에 배포 도메인을 등록합니다. VWorld 키는 등록한 도메인에서만 동작합니다.
3. 환경 변수 등록

```bash
VWORLD_API_KEY=발급받은_인증키
VWORLD_REFERER=https://배포도메인   # 서버에서 부를 때 보낼 Referer (선택)
```

키가 없으면 `[예시 응답 보기]` 로 실제로 받아 둔 응답을 확인할 수 있습니다.

### 이 연동이 특히 값어치를 하는 곳

**도로명주소만 있을 때 지번을 찾아 줍니다.** 도로명으로는 건축물대장을 조회할 수 없습니다 — 건물번호는 번지가 아니기 때문입니다. VWorld 는 도로명으로 좌표를 잡고, 그 좌표가 올라앉은 필지를 연속지적도에서 되짚어 지번과 PNU 를 냅니다. 그래서 **[필지 조회] 를 먼저 돌리면 [대장 조회] 가 열립니다.**

```
도로명주소 "인천 부평구 열우물로 90"
   → 지오코딩 → 좌표 (126.70007, 37.47593)   ← PNU 없음
   → 연속지적도 POINT 조회 → PNU 2823710200106300000
   → 지번 "인천광역시 부평구 십정동 630" · 건축물대장 조회 키
```

| 조회 | 레이어 · 엔드포인트 | 나오는 것 |
|---|---|---|
| 지오코딩 | `req/address getcoord` | 좌표, 정제 주소, 지번이면 PNU |
| 필지 | `LP_PA_CBND_BUBUN` 연속지적도 | PNU, 지번, 지목, 개별공시지가(원/㎡) |
| 용도지역 | `LT_C_UQ111` | 준주거지역 등 용도지역 이름과 결정 연도 |

| 파일 | 역할 |
|---|---|
| `src/lib/vworld.ts` | PNU 변환, 응답 정규화, 오류 문구. 의존성 없는 순수 함수 |
| `src/app/api/vworld/route.ts` | VWorld 프록시. 지오코딩 + 필지 + 용도지역을 한 번에 |
| `src/components/property/ParcelLookup.tsx` | 필지 조회 카드 |
| `src/data/vworldSample.ts` | 실제로 받아 둔 응답 (테스트 입력이자 예시 화면 데이터) |

### 값을 다룰 때 지킨 것

- **PNU 의 필지구분과 건축물대장의 대지구분은 숫자가 다릅니다.** PNU 는 1=일반·2=산, 대장은 0=대지·1=산입니다. 그대로 넘기면 산 번지가 조회되지 않습니다. 두 경우 모두 실제 응답으로 확인해 테스트에 넣었습니다.
- **연속지적도에는 면적이 없습니다.** 그래서 `Parcel` 타입에 면적 자체를 두지 않았습니다. 토지가액은 사용자가 면적을 입력했을 때만 `공시지가 × 면적` 으로 산출하고, 없으면 "면적 입력 시 산출" 로 둡니다.
- **도메인 미등록은 키 오류와 조치가 다릅니다.** VWorld 가 가장 흔하게 내는 실패라서 별도 문구(`DOMAIN`)로 안내합니다.
- **필지·용도지역 조회가 실패해도 좌표는 돌려줍니다.** 지적 경계 갱신 중이면 필지만 비고, 나머지는 그대로 씁니다.

### 테스트

```bash
npm test    # 건축물대장 12개 + VWorld 10개
```

## 알림톡 실패 시 문자 대체발송

알림톡은 카카오톡을 쓰지 않거나 채널을 차단한 고객에게는 **꽂히지 않습니다**.
계약일·잔금일 안내가 그렇게 조용히 누락되면 그건 사고입니다.
그럴 때 같은 내용을 문자(SMS/LMS)로 대신 내보냅니다.

### 대체발송은 "실패한 뒤에 보내는" 것이 아니다

이 연동의 모든 설계가 여기서 나옵니다.

```
알림톡 요청  ──┬── 알림톡 본문
               └── 예비 문자 본문   ← 같이 실려 나간다
                        │
        카카오톡으로 꽂힘 → 문자 폐기, 알림톡 6.5원만 과금
        못 꽂음          → 대행사가 문자를 내보냄, 문자 요금 추가 과금
```

따라오는 결과 두 가지:

1. **문구가 발송 전에 준비돼 있어야 합니다.** 그래서 대체 문구는 템플릿에 딸려 있습니다(`Template.sms`). 실패를 보고 그때 쓰는 게 아닙니다.
2. **요청 자체가 접수되지 않으면 문자도 안 나갑니다.** 대행사 장애(현재 샘플의 `vendor_ssl`)는 알림톡과 예비 문자가 **함께** 보류됩니다. 이걸 "대체발송을 켰는데 왜 안 왔지"로 오해하지 않도록 발송 내역에 그대로 적습니다.

### 켜는 방법

1. **설정 › 발송 계정**에서 대체발송을 켜고 하루 상한을 정합니다.
2. **템플릿 관리**에서 템플릿마다 대체 문구를 넣고 켭니다. 계약일·중도금·잔금·만료일·등기부 변동만 켜 두는 것이 기본값입니다.

문자 발신번호는 **전기통신사업법 제84조의2에 따라 미리 등록**해야 합니다.
알림톡과 별개 절차라, 카카오 채널만 있으면 알림톡은 나가도 대체 문자는 한 건도 나가지 않습니다.

### 실패 사유마다 문자가 나가는지가 다르다

한 덩어리로 처리하면 왜 안 갔는지 알 수 없습니다. `FAIL_REASONS[code].fallback`:

| 정책 | 실패 사유 | 문자 |
|---|---|---|
| `auto` | 카카오톡 미사용 · 채널 차단 | 나간다 — 대체발송이 존재하는 이유 |
| `choice` | 수신 거부 | 중개사가 켜야 나간다 |
| `duplicate` | 결과 회신 없음 | 자동으로 안 보낸다 — 알림톡이 갔을 수도 있어 두 번 받는다 |
| `blocked` | 번호 오류 · 대행사 장애 | 못 나간다 (번호가 틀렸거나 요청이 접수되지 않음) |

### 값을 다룰 때 지킨 것

- **한글은 한 글자가 2바이트**입니다. 문자 표준이 EUC-KR 기준이라 SMS 90바이트 = 한글 45자입니다. 글자 수로 세면 두 배로 틀립니다.
- **변수가 채워지면 길이가 바뀝니다.** `#{물건명}` 하나가 "더샵부평센트럴시티 110동 103호"로 치환되면 SMS가 LMS가 되고 단가가 2.5배입니다. 그래서 바이트는 **치환된 문장**으로 재고, "예시 값으로 잰 것"이라고 화면에 적습니다.
- **비용은 총액을 지어내지 않습니다.** 몇 건이 실패할지는 보내 봐야 알기 때문에, 발송 화면에서는 건당 단가만 보여 주고 "실패한 건만 과금된다"고 적습니다.
- **이모지 경고는 좁게 잡습니다.** `★ ※ ♥ ☎` 는 EUC-KR 에 멀쩡히 있습니다. 넓게 잡아 멀쩡한 문구에 경고가 뜨면 경고 자체를 안 믿게 되므로, 확실한 것(0xFFFF 초과 · U+FE0F · U+2B00~2BFF)만 잡고 놓치는 쪽을 택했습니다.
- **알림톡 본문에 없는 변수는 막습니다.** 문자는 카카오 검수가 안 봐 주므로 `#{고객명}` 이 글자 그대로 고객에게 갑니다.
- **문자에는 채널명 머리도 버튼도 없습니다.** 초안을 만들 때 상호를 본문 앞에 붙이고, 주소를 아는 버튼만 링크로 풀고, 못 옮긴 버튼은 화면에서 알립니다.
- **하루 상한**을 둡니다. 문자는 알림톡의 3~8배라 상한이 없으면 대량 발송 한 번에 예치금이 빕니다.

## 정기결제 (포트원 · 토스페이먼츠)

무료 체험이 끝나면 자동발송이 멈춥니다. 그전에 결제를 받을 방법이 필요합니다.

### 카드 정보는 이 서비스가 갖지 않는다

여신전문금융업법상 가맹점은 카드번호·유효기간·CVC 를 저장할 수 없습니다.
그래서 구조가 이렇게 됩니다.

```
① 카드 등록
   브라우저 ──카드번호──▶ PG 결제창 (포트원/토스페이먼츠)
   PG ──빌링키──▶ 부동산TALK 서버     ← 우리가 받는 건 이것뿐

② 결제할 때
   부동산TALK 서버 ──빌링키 + 서버가 계산한 금액──▶ PG
```

화면에 보이는 "신한 신용카드 ···· 1234" 도 우리가 가진 카드번호가 아니라
PG 가 표시용으로 내려준 값입니다. 카드 등록 화면에는 입력칸이 하나도 없습니다.

### 금액은 요청 본문에서 읽지 않는다

`src/lib/billing.ts` 의 `PLANS` 가 서버가 믿는 유일한 가격표입니다.
브라우저가 보낸 금액을 그대로 쓰면 1원으로 유료 플랜을 살 수 있습니다.
API 는 "누가 · 어떤 플랜을 · 어떤 주기로"까지만 받고 금액은 서버가 정합니다.

### 웹훅은 알림이지 결제 결과가 아니다

웹훅 주소는 인터넷에 열려 있습니다. 본문을 믿고 이용기한을 늘리면
누구든 성공 웹훅을 흉내 내 유료 플랜을 공짜로 씁니다. 그래서 두 겹으로 봅니다.

1. **서명 검증** — 포트원은 Standard Webhooks 서명을 줍니다(`src/lib/webhook.ts`).
   본문 원문을 대상으로 HMAC 을 맞춰 보고, 5분보다 오래된 서명은 가로챈 요청의
   재전송으로 보고 막습니다. 토스페이먼츠는 서명이 없어 이 단계가 없습니다.
2. **재조회 대조** — PG API 로 그 결제를 다시 읽습니다. 이용기한을 늘리는 근거는
   웹훅 본문이 아니라 이 응답입니다. 주문번호에서 읽은 플랜·주기의 가격과
   실제 입금액이 다르면 성공으로 처리하지 않습니다.

### 같은 결제가 두 번 청구되지 않게

주문번호가 `jt_{회원}_{플랜}_{m|y}_{YYYYMMDD}` 라서, 같은 결제는 몇 번을 요청해도
같은 값이 나옵니다. PG 는 이 값이 겹치면 거절하고, 토스는 `Idempotency-Key` 로도
한 번 더 막습니다. 주기(`m`/`y`)를 넣어 둔 이유는 따로 있습니다 — 웹훅이 금액을
대조하려면 주문번호만 보고 "이건 얼마여야 하는가"를 알 수 있어야 합니다.

### 실패했을 때

실패 사유마다 다음에 할 일이 다릅니다. 이건 알림톡 대체발송과 같은 구조입니다.

| 정책 | 실패 사유 | 다음 |
|---|---|---|
| `retry` | 잔액·한도 부족, 카드사 점검, 사유 미상 거절 | D+1 · D+3 · D+7 세 번까지 |
| `card` | 유효기간 만료, 분실·도난, 정지, 빌링키 무효 | 재시도하지 않는다 — 카드를 바꿔야 한다 |
| `stop` | 회원이 해지함 | 재시도 대상이 아니다 |

무한 재시도는 카드사가 어뷰징으로 보고 가맹점을 막기 때문에 세 번에서 끊습니다.

**결제가 실패해도 그날 바로 끊지 않습니다.** 유예 7일 동안은 이미 예약된
자동발송이 그대로 나갑니다. 이 서비스에서 자동발송이 멈춘다는 건 회원의 고객이
계약일·잔금일 안내를 못 받는다는 뜻이라, 결제 문제로 그걸 끊으면 피해가
회원이 아니라 그 고객에게 갑니다.

### 날짜 계산에서 틀리기 쉬운 것

- **말일**: 31일에 시작한 결제는 1/31 → 2/28 → **3/31** 입니다. 2월에 당긴 28일을
  새 기준으로 삼으면 그 뒤로 영영 28일이 됩니다. 그래서 기준일(anchor)을 따로 들고 다닙니다.
- **부가세 역산**: 공급가액을 원 단위로 떨어뜨리고 나머지를 부가세로 둬야
  세금계산서 합계가 청구액과 맞습니다.
- **일할계산**: 올릴 때만 남은 기간 차액을 받고, 내릴 때는 받지 않습니다.
  원 단위는 내려서 청구합니다 — 반올림으로 1원을 더 받는 쪽으로 기울지 않게.
- **환불액**: 정가가 아니라 **실제로 낸 마지막 결제**를 근거로, 구독 시작일이 아니라
  **그 결제일**부터 쓴 날을 셉니다. 차액만 낸 회원에게 정가를 돌려주면 안 됩니다.

### 켜는 방법

```
PORTONE_API_SECRET=...        # 포트원을 쓸 때
PORTONE_WEBHOOK_SECRET=...    # 없으면 웹훅을 아예 받지 않습니다
TOSS_SECRET_KEY=...           # 토스페이먼츠를 쓸 때
```

둘 중 하나만 채우면 그쪽으로 붙습니다. 웹훅 주소는 `/api/billing/webhook` 입니다.

### 테스트

```bash

```

웹훅 서명은 본문을 한 글자 바꾸거나, 다른 키로 서명하거나, 오래된 서명을 다시 보내면
막히는지까지 확인합니다.

## 첨부 파일 저장소 (S3 호환)

계약서·확인설명서·등기부등본을 계약에 붙여 두고, 고객에게는 골라서 보여 줍니다.

### 부동산에서 파일은 "그냥 파일"이 아니다

세 가지가 한꺼번에 걸립니다.

- **보존기간이 법으로 정해져 있습니다.** 공인중개사법상 거래계약서는 5년,
  중개대상물 확인·설명서는 3년 보존해야 합니다.
- **보존기간이 지나면 지워야 합니다.** 쌓아 두는 것 자체가 개인정보보호법 위반입니다.
- **신분증 사본에는 주민등록번호가 들어갑니다.** 법령 근거 없이 보관할 수 없습니다.

그래서 파일마다 **종류**를 먼저 정하고, 그 종류가 나머지를 전부 정합니다.

| 종류 | 공개 | 보존 | 받는 형식 | 크기 |
|---|---|---|---|---|
| 계약서 | 아니오 | 5년 | pdf jpg png | 20MB |
| 확인설명서 | 아니오 | 3년 | pdf jpg png | 20MB |
| 등기부등본 | 아니오 | 3년 | **pdf만** | 10MB |
| 신분증 | 아니오 | **3개월** | pdf jpg png | 10MB |
| 물건사진 | **예** | 없음 | jpg png webp | 10MB |

물건사진만 공개입니다 — 광고에 쓰라고 올리는 것이니까요. 계약서는 절대 아닙니다.
신분증을 고르면 "꼭 필요한 경우가 아니면 올리지 마세요" 경고가 먼저 뜹니다.

보존기간이 지난 파일은 목록에서 빨갛게 표시하고 위에 **"파기 대상 N건"** 배너를 띄웁니다.
기한은 연도까지 적습니다 — "8월 15일까지 보존"이라고만 쓰면 5년 뒤 날짜가 올해로 읽혀서
아직 보관해야 할 계약서를 지우게 됩니다.

### 파일은 서버를 지나가지 않는다

Vercel 서버리스 함수는 요청 본문이 **4.5MB** 로 막혀 있습니다. 계약서 스캔 PDF 는
그걸 쉽게 넘습니다. 그래서 이렇게 나눕니다.

```
① 브라우저 → 서버      "계약서.pdf 2.4MB 올리려는데요"
② 서버 → 브라우저      이름·크기·종류를 검사하고, 10분간 유효한 서명된 주소를 내줌
③ 브라우저 → 저장소    파일을 바로 올림 (서버를 안 거치니 크기 제한이 없음)
④ 브라우저 → 서버      "다 올렸습니다"
⑤ 서버 → 저장소        앞 16바이트만 되읽어 내용이 이름과 맞는지 확인, 아니면 삭제
```

**⑤가 핵심입니다.** 브라우저가 바로 올리면 서버는 파일 내용을 못 봅니다. 검사를
브라우저에만 맡기면 검사를 건너뛴 요청이 그대로 통과합니다. 그래서 올라간 뒤에
서버가 앞부분을 되읽어 **매직 바이트**로 실제 형식을 확인하고, 이름과 다르면 지웁니다.
확장자는 누구나 바꿀 수 있어서 `.pdf` 로 이름 붙인 실행 파일이 그냥 올라갑니다.

### 주소가 새도 내용을 짐작할 수 없게

저장 경로에 파일 이름을 쓰지 않습니다.

```
올린 이름   김민수_주민등록증.jpg
저장 경로   deals/d1/RD94CajI-J1WP1gp.jpg     ← 이름이 남지 않는다
```

내려받기는 저장소 주소를 브라우저에 주지 않고 `/api/files?key=…` 를 거칩니다.
서버가 권한을 확인한 뒤 **2분간만 사는** 주소로 넘깁니다. 권한 확인이 들어갈 자리를
만들려고 한 번 더 거치게 한 것입니다.

고객은 중개사가 **"고객에게 보이기"를 켠 서류만** 봅니다. 신분증은 켤 수 없게 하지 않고
기본값을 꺼 두었습니다 — 켜야 하는 상황이 없지는 않기 때문입니다.

### 어디에 붙여도 되게

라이브러리 없이 AWS SigV4 서명을 직접 만듭니다(`src/lib/s3sign.ts`).
Cloudflare R2 · AWS S3 · Supabase Storage · MinIO 어디든 같은 코드가 붙습니다.

```
S3_ENDPOINT=https://<계정ID>.r2.cloudflarestorage.com
S3_BUCKET=...
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
# S3_REGION=auto        # R2 는 auto, AWS 는 ap-northeast-2 처럼
```

버킷은 **비공개로 두세요.** 공개로 열면 주소를 아는 사람이 계약서를 봅니다.
브라우저에서 바로 올리므로 버킷 CORS 에 배포 도메인을 PUT 허용으로 등록해야 합니다.

### 테스트

```bash
npm test        # 18개 — 매직 바이트, 경로 조작, 보존기간, 한글 파일명, 서명
```

확장자만 바꾼 실행 파일이 막히는지, `../../etc/passwd` 가 `passwd` 로 정리되는지,
5년·3년·3개월 보존기간이 말일·윤년까지 맞는지, 서명 쿼리가 정렬되는지까지 확인합니다.

## 설계 메모 (검토 보고서 대응)

- **내비게이션**: 좌측 고정 사이드바 5그룹 + 현재 위치 강조 + 상단 경로. '대시보드로' 버튼과 툴바 이동 버튼 제거. (C-01, C-02, T-01)
- **대시보드**: 첫 줄이 '오늘 할 일' 4타일. 정상 상태는 숨기고 이상만 배너·알림으로. 캘린더 하나. 유익한 사이트는 별도 메뉴. (D-01~D-07)
- **행동의 무게**: 주요 버튼은 화면당 1개, 삭제·강제종료·예약 취소는 더보기 메뉴 + 대상명이 보이는 확인 모달. 성공은 토스트(되돌릴 수 있는 행동은 '실행 취소' 포함). (C-07, C-08, C-22)
- **오류 표현**: 실패 코드 → 사람 문장 매핑(`src/data/sends.ts`의 `FAIL_REASONS`), 기술 원문은 '자세히' 뒤. 대행사 장애는 화면 상단 배너 한 줄. (C-09, C-10, S-01, S-03)
- **지금 발송**: '5분뒤 발송'이 주 버튼, '바로 발송'은 보조 + 강한 확인. 대상 0명이면 비활성. 발송 전 요약(대상·제외·비용·시점). (IS-01, IS-02)
- **폼**: 등록은 슬라이드 패널, 라벨 위, 관련 필드 2열, 조건부 필드(계약방식에 따라 금액 칸이 바뀜), 동의 체크는 기본 해제. (C-15, C-21, CU-01)

- **표**: 기본 열 축소, 상태 배지, 첫 열 고정(회원 관리), 행 클릭 상세, 빈 값 '—', 페이지네이션 한 벌. (P-01, DL-03, AM-02, C-06, C-11)

# LAND LANGUAGE 브리핑 — 중개사용 STUDIO + 고객용 LETTER

안양 공인중개사무소를 위한 부동산 정책·시장 브리핑 서비스입니다. 정부 보도자료·언론 기사·안양시 고시를 모아
5축(발표 주체 · 정책 단계 · 주제 · 영향 대상 · 지역)으로 태깅하고, 중개사는 **스튜디오**에서 검수·선택하며,
고객은 세그먼트별로 3~8개 이슈만 쉬운 말로 담은 **읽기 전용 레터**를 받습니다.

기획 배경과 규칙(R1~R8)은 [`docs/plan-customer-broker-split.md`](docs/plan-customer-broker-split.md) 를 참고하세요.

## 화면

스튜디오 상단은 원본 EDM 스튜디오의 뼈대를 그대로 씁니다. 짙은 남색 바 한 줄에 **DAILY / WEEKLY / MONTHLY** · **이메일 / 모바일 / 인스타 카드 / 블로그 포스팅** · **🏢 사무소 · ✉ 메일 · 🖨 PDF·인쇄 · 💬 카카오톡 · 🔗 링크** · `실시간 뉴스 · 09. 12. 오후 07:45 수집`. 메일·카카오톡·링크는 가장 최근에 발행한 고객용 레터를 기준으로 동작합니다(발행 전이면 레터 빌더로 안내). 그 아래 얇은 줄에 이 서비스에만 있는 인박스·레터 빌더·우리 동네 숫자·설정이 있습니다. 배경은 항상 밝은 톤으로 고정되어 있습니다(OS 다크 모드를 따르지 않음).

## Vercel 배포

1. 이 저장소를 GitHub 에 두고 Vercel 에서 **Import** 합니다. 프레임워크는 Next.js 로 자동 인식됩니다.
2. 환경변수를 넣습니다 (`.env.example` 참고).

   | 변수 | 필수 | 설명 |
   |---|---|---|
   | `STUDIO_PASSWORD` | 권장 | 스튜디오(`/studio`, `/api/studio/*`) 접근 비밀번호. 비우면 누구나 접근 가능 |
   | `KV_REST_API_URL`, `KV_REST_API_TOKEN` | 권장 | Upstash Redis. Vercel Marketplace → Upstash 연동 시 자동 주입. 없으면 배포 환경에서는 메모리 저장(재시작 시 초기화) |
   | `CRON_SECRET` | 권장 | Vercel Cron 이 `Authorization: Bearer` 로 보내는 값. 설정 시 크론 엔드포인트가 보호됩니다 |
   | `ANTHROPIC_API_KEY` | 선택 | 수집된 이슈의 고객용·중개사용 초안을 Claude 가 작성(기본 모델 `claude-opus-5`, `ANTHROPIC_MODEL` 로 변경). 검수 후 발행 |
   | `DATA_GO_KR_KEY` | 선택 | 공공데이터포털 실거래가 API 키. 안양 실거래 집계 자동 갱신 |
   | `ECOS_API_KEY` | 선택 | 한국은행 ECOS API 키. 기준금리 자동 갱신 |
   | `NEXT_PUBLIC_SITE_URL` | 선택 | 발행 URL 생성에 쓸 사이트 주소(예: `https://brief.example.com`) |

3. **Deploy**. 배포 직후 샘플 이슈 10건과 샘플 레터(`/l/demo`)가 들어 있습니다.
4. 크론은 `vercel.json` 에 정의되어 있습니다.
   - `/api/cron/collect` 매일 07:00 KST (22:00 UTC) — 보도자료·기사 수집 + 자동 초안(키가 있을 때)
   - `/api/cron/market` 매일 06:00 KST (21:00 UTC) — 실거래·기준금리 갱신(키가 있을 때)
   - Hobby 플랜은 하루 1회 실행이 한도입니다. Pro 플랜이면 `schedule` 을 `0 */3 * * *` 처럼 줄일 수 있습니다. 스튜디오의 **지금 수집** 버튼으로 언제든 수동 실행할 수 있습니다.

### 브리핑 본문 구조 (중개사용 그린 · 고객용 남색 공통, 원본 EDM 순서)

1. 마스트헤드 — 사무소명 · 공인중개 · 브랜드 · `DAILY BRIEFING · 날짜`
2. 슬로건 인용구
3. `TODAY'S / THIS WEEK'S / THIS MONTH'S REAL ESTATE BRIEF` + 헤드라인
4. **오늘(이번 주·이달) 꼭 알아야 할 정책** · 공식 고시·발표 종합 — 카드: 발표 주체·날짜·단계 → 제목 → ✓ 할 일(중개사용은 팩트·상담 포인트·실무 체크) → 영향도 분석 → **원문·관련보도 보기** → 관련 보도 3건 → 최신 뉴스 검색 · 참고 사이트
5. **오늘의 주요 뉴스** · 기사 제목을 누르면 원문으로 이동 — 고객용은 입법예고·검토·언론 보도 단계 사안을 제목·기사 링크만으로 싣습니다(해설 없음)
6. **오늘의 숫자** · 출처·기준일이 확인된 수치만 게시 — 안양 실거래 집계·기준금리 타일 + 추이 차트
7. **그래서 내 부동산에는?** — 헤드라인 이슈 기준 무주택자·1주택자·다주택자·매수 예정자·매도 예정자·임대인·임차인 영향도와 한 줄, 용어 하나
8. 공인중개사의 한마디 · 전문가 코멘트
9. CTA — 이 정책이 내 집에 어떤 영향을 주는지 궁금하신가요? (전화 · 카카오톡)
10. 사무소 안내 · 법적 고지 · 수신거부·개인정보처리방침

### 수집 주제 축 — 왜 기관이 아니라 주제로 묶는가

수집은 **주제(C축) 기준**입니다. 피드 9개 중 8개가 주제별 뉴스 검색(정책·금리·세금·임대차·청약분양·정비사업·안양·중개업)이고, 나머지 하나가 정부 보도자료 통합 RSS 입니다.
발표 기관(A축)은 묶는 기준이 아니라 **확정 여부를 판정하는 보조 축**으로만 씁니다.

- **한 사건은 여러 출처에서 동시에 나옵니다.** 샘플 10건에 관련 기사 43건이 붙어 있고 출처는 32곳입니다. 기준금리 이슈 하나에만 언론사 6곳이 걸립니다. 출처별로 나누면 한 사건이 여섯 칸으로 흩어집니다.
- **한 기관은 여러 주제를 냅니다.** 샘플에서 국토교통부 한 곳이 공급·중개업 제도·청약을 동시에 냅니다. 기관으로 묶으면 고객이 찾는 단위와 어긋납니다.
- **고객은 주제로 묻습니다.** "우리 동네 재개발 어떻게 됐어요", "전세 지금 구해도 되나요"로 묻지, "부동산원 자료 있어요"로 묻지 않습니다. 카드뉴스·블로그 제목도 주제 단위로 서야 검색에 걸립니다.
- **기관은 신뢰 판정에 씁니다.** 같은 내용이라도 국토부 보도자료면 확정·시행, 언론 단독이면 언론 보도로 B축 단계가 갈립니다. 이 단계가 R1(고객 본문 vs 주요 뉴스)을 결정합니다.

주제는 10종 고정입니다. 금리·대출 / 세금 / 청약·분양 / 공급·택지·신도시 / 정비사업 / 임대차·전세 안전 / 교통·개발 / 시장 통계 / 규제지역·거래허가 / 중개업 제도.
재개발이나 분양 한 가지로 좁히지 않는 이유는 세그먼트 때문입니다. 내집마련 고객은 청약·임대차·금리를, 자산·임대 고객은 세금·임대차·정비사업을 봅니다.
한 주제만 다루면 나머지 두 세그먼트에 보낼 레터가 비어 버립니다. 대신 **지역(E축)과 영향도(D축)로 가중치**를 줍니다. 안양 고시·정비사업은 동네 타깃으로 맨 앞에 서고(R3), 세그먼트 영향도 3 미만은 본문에서 빠집니다.
### 주력 주제 (설정 → 주력 주제)

사무소마다 강한 주제가 다르므로 **주력 주제**를 2~4개 고를 수 있습니다. 고른 주제는 인박스 칩에 ★ 로 표시되고, **같은 등급·같은 영향도일 때만** 앞으로 옵니다.
규칙 R1~R8(고객 본문 여부 · 분량 · 신선도 · 같은 주제 2개 상한)은 그대로라 다른 주제가 사라지지 않습니다. 비우면 가중치 없이 최신순으로만 정렬합니다.

기본값은 안양 만안·동안 동네 사무소 기준 추천 조합 **정비사업 · 임대차·전세 안전 · 금리·대출** 입니다.

| 주제 | 고른 이유 |
|---|---|
| 정비사업 | 동네 독점 정보입니다. 수촌마을·충훈부 구역 소식은 전국 매체가 다루지 않아 검색 경쟁이 낮고, 조합원 물건 문의로 바로 이어집니다 |
| 임대차·전세 안전 | 거래 빈도가 가장 높고 임차인·임대인 양쪽이 고객입니다. 전세사기 이후 상담 수요가 가장 큽니다 |
| 금리·대출 | 세 세그먼트 모두 영향도 3 이상인 유일한 축입니다. "지금 사도 되나요" 문의의 출발점입니다 |

일부러 뺀 주제도 있습니다. **세금**은 영향은 크지만 세무사 영역이라 중개사가 단정적으로 쓰기 어렵고, **중개업 제도**는 R2 로 고객에게 나가지 않아 중개사용 브리핑에서만 보면 됩니다.
**청약·분양**은 안양 신규 분양 물량이 적어 상담 전환이 낮습니다. 사무소 사정이 다르면 설정에서 언제든 바꿀 수 있습니다.

반영되는 곳은 네 군데입니다. 인박스 정렬과 '주력 주제만' 필터, 중개사용 브리핑 카드 순서, 레터 빌더의 이슈 선정 순서, 인스타·블로그의 주제 목록 순서.

인박스 상단의 주제 칩으로 언제든 한 주제만 볼 수 있습니다.

### 링크 규칙

- 카드의 큰 버튼 **원문·관련보도 보기**는 항상 기사·보도자료 원문(대표 기사 = 이슈를 만든 기사)으로 갑니다. 대표 기사가 공식 문서면 '원문 보기'로 표시됩니다.
- 특정 보도자료·고시 문서가 따로 있으면 **공식 원문** 버튼이 붙습니다. 목록·통계 페이지(부동산원 R-ONE, 국토부 보도자료 목록 등)는 공식 원문으로 치지 않고 '참고 사이트'에만 둡니다.
- **관련 보도**는 대표 기사를 뺀 나머지 기사 최신순 3건, **최신 뉴스 검색**은 제목 키워드로 네이버 뉴스(최신순)·구글 뉴스 검색을 엽니다. 수집이 멈춰 있어도 최신 기사에 닿는 통로입니다.
- **참고 사이트**(공공데이터 바로가기)는 작은 글씨로 카드 맨 아래에만 둡니다.

### 라우팅 규칙 요약

- **R1** 확정·시행 예정·통계·지자체 고시만 고객 본문. 입법예고·국회 심의·정부 검토·언론 보도·전망은 '주요 뉴스' 카드(제목·기사 링크만, 해설 없음).
- **R2** 중개업 제도(중개보수·임장비·확인설명 의무 등)는 중개사 전용. 시행 확정 시에만 한 줄.
- **R3** 안양시 고시·동네 사안은 해당 동을 지정한 레터에만.
- **R5** 서울 통계는 안양 '우리 동네 숫자'로 치환.
- **R7** 고객용 금지 표현(고객에게 · 안내하세요 · 설명하세요 · 상담 시 · 영업 · 경쟁 · 수주 · 협회 · DEMO · 입력해 주세요 · 미설정)이 있으면 발행 차단.
- **R8** DAILY 3개(48시간) · WEEKLY 5개(7일) · MONTHLY 8개(31일), 같은 주제 2개까지.

## 구조

```
app/                 Next.js App Router (studio, l/[id], api/studio/*, api/cron/*)
components/          LetterView(고객 레터 렌더러), Badges
lib/                 types · taxonomy · links(공공데이터 바로가기) · classify · routing · letter · market · collect · enrich · store · repo · seed
data/market-anyang.json   안양 실거래 월별 집계(기존 monthly.json) + 기준금리
public/anyang-dashboard/  기존 대시보드 사본
docs/                기획안
```

저장소는 `lib/store.ts` 어댑터로 추상화되어 있습니다. Upstash 대신 다른 KV/DB 를 쓰려면 `KV` 인터페이스(`get`/`set`)만 구현하면 됩니다.

## 주의

- 자동 초안은 초안일 뿐입니다. 검수 완료로 바꾸기 전에는 레터에 실리지 않습니다.
- 블로그 초안의 🖼️ [이미지 추가위치]는 주황 점선 상자, ✍️ [직접 경험 입력]은 노란 상자로 표시됩니다. 두 자리를 채우기 전에는 발행하지 마세요. 문서 상단 메타 줄에 남은 칸 수가 나옵니다.
- 인스타 카드 PNG 저장은 브라우저에서 `html-to-image` 로 렌더링합니다. 웹폰트가 이미지에 포함되지 않으면 기본 글꼴로 저장될 수 있으니 저장 결과를 한 번 확인하세요. 카드·블로그 본문은 고객용 문장에서 가져오며, R7 금지 표현이 있으면 화면에 경고가 뜹니다.
- 실거래 신고 기한이 30일이라 최근 두 달 집계는 잠정치로 표시됩니다.
- 광고성 메일 발송에는 실제로 동작하는 수신거부 수단이 필요합니다. 설정의 수신거부 링크 또는 이메일을 채우세요.
- `fetch.js` 등 루트의 기존 스크립트에 들어 있던 API 키는 환경변수(`DATA_GO_KR_KEY`)로 옮기고 재발급하는 것을 권합니다.
